# Compatible Frobenius optimization toward 20 B iterations/sec

The current validated implementation reaches **19.369113 B point updates/sec**
on one RTX PRO 6000 Blackwell Server Edition, compared with **17.676342 B/sec**
for v3 on the same GPU. The median paired improvement is **9.593472%**; all five
pairs improved. **The requested sustained 20 B/sec target has not been reached.**
Further experiments are in progress; their short screens are not production
throughput claims.

## Implementation

- Compute Frobenius differences in expanded polynomial coordinates. The
  complement representing the field unit cancels in `x + sigma(x)`. The hot
  path avoids the final normal-basis shift/complement and the corresponding
  input shift in the conversion back. The Hamming weight accounts for the
  complement flag, and reports still convert to canonical coordinates.
- Route the 130 live shifted input wires through a frozen, independently
  checked permutation network. Its byte swaps use byte permutations and
  symmetric masks. The 132-bit intermediate is converted back before storage.
- Compose the word-aligned tail of the polynomial conversion and align the
  modular-reduction circuit directly to the unreduced high words. Generators
  check these linear maps against basis vectors and polynomial long division.
- Reduce the polynomial square through its even and odd coefficient streams,
  and schedule the three-bit product correction independently of the native
  128-bit product. The square generator checks 10,133 inputs against long division.
- Keep the inverse chain in the normal basis with the existing two-product
  multiplier, use constant permutations for its fixed powers, and rotate the
  inverse roots across warp positions between steps.
- Fold the middle Karatsuba terms and the lower three-bit correction into
  native carryless XOR addends. The upper output cancels that correction and
  adds its own; this shortens the path feeding the modular reducer. Defer the
  dead-point read until the reporting/guard condition.

The changed arithmetic paths are selected by the fused Frobenius profile.
The ordinary canonical Frobenius API and other reducer profiles retain their
existing contracts. The measured kernel uses 91 registers per thread, no local
spill storage, and 14,752 bytes of shared memory per block.

## Validation

The confirmation passed all 17 fresh-state/corpus and bidirectional-resume
comparisons. These cover worker counts 640, 641 and 256, DP weights 0 and 50,
odd launch lengths 1, 3 and 17, and a 4,097-step launch crossing the iteration
guard. Every checkpoint comparison is byte-for-byte.

GPU checks passed: 18,194 polynomial product cases (including every basis pair),
18,194 paired-product cases, 2,526 reductions, 1,157 squares, 3,120 scalar
Frobenius vectors, 6,240 ordinary paired Frobenius vectors, and 6,240 shifted
Frobenius-difference vectors. The latter use independent polynomial squaring
and long division and check output guards, inactive blocks, coordinate recovery,
and the complement-dependent weight. The existing shared-mask test also passed
all 21 scenarios and 114 complete snapshots. Storage checks covered 297,344
records with independent physical images and canaries.

Local generator/CLI checks and the host arithmetic reference checks passed.
The host arithmetic build explicitly enabled the fused Frobenius, normal-basis
inverse, generated product and direct reduction settings.

## Reproduction

From `ecc2k130/runner`, build the candidate and run its GPU checks:

```sh
make gpu-frobenius32-120k
make check-production-gpu
```

The isolated validator rebuilds the pinned v3 control and the current source,
performs the warmed comparison and the GPU/compatibility checks, and writes a
receipt. It uses temporary files and no campaign credentials or volumes:

```sh
modal run validate_frobenius_20b.py --mode confirm --selected production_onb \
  --output research/production/frobenius-20b-recheck.json
```

The two-run arithmetic screen reached 20.085774 B/sec, but warmed production
confirmation reached the lower rate above. A subsequent paired screen of the
prototype and production integration on the same GPU differed by less than
0.1%; their preprocessed hot arithmetic matches. Short boost measurements
do not establish the requested sustained target.
