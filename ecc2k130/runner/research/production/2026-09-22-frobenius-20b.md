# Compatible Frobenius: confirmed 20 B iterations/sec

CUDA **13.4.92** builds the compatible Frobenius DP32 implementation at a
**20.214524 B point updates/sec median** across five warmed, alternating pairs
on one RTX PRO 6000 Blackwell Server Edition GPU. Every candidate sample exceeds
20 B/sec; the slowest is **20.198750 B/sec**. The full GPU suite and all 17
checkpoint/corpus and bidirectional-resume comparisons pass.

The [complete confirmation receipt](2026-09-22-frobenius-20b-cuda134-direct-confirm.json)
compares the same application source with CUDA 13.3.73 and CUDA 13.4.92. The
median paired gain is **1.074554%**. The control is pinned to commit
`69f5e687e937d04902f195eca5228d029c4d29cd`.

| Pair | CUDA 13.3 B/sec | CUDA 13.4 B/sec | Paired gain |
| --- | ---: | ---: | ---: |
| 1 | 20.085540 | 20.274737 | 0.941956% |
| 2 | 20.023736 | 20.251791 | 1.138923% |
| 3 | 20.006196 | 20.214524 | 1.041317% |
| 4 | 19.988988 | 20.212784 | 1.119596% |

## Scope and measurement

Each sample runs 128 launches of 1,024 steps after a 512-launch post-build
warmup. The control/candidate order alternates. The worker population remains
120,320, batch size 16, block size 640, and collective group size four warps:
1,925,120 point streams. Timing includes report handling and the final reseed.
The long samples disable CPU replay; dense short compatibility runs separately
replay every reported point against the independent CPU reference.

GPU UUID: `GPU-51e0c576-dded-81ad-029c-43a19d6849eb`. Driver: `580.95.05`.
The GPU uses its default 600 W limit; no clock or power setting was changed.
Candidate active SM-clock medians range from 2,370 to 2,385 MHz, at 68–70 C.
The candidate's median clock is equal to or below the control's in every pair.
Telemetry samples the complete process every 500 ms and excludes samples below
2,000 MHz from active medians; initial GPU seeding is included.

This GPU also runs the CUDA 13.3 control faster than earlier machines: its
20.006196 B/sec median includes two individual samples below 20 B/sec. Therefore,
the rise from the earlier 19.921969 B/sec result is not solely a compiler gain.
The direct 1.074554% gain is the supported incremental comparison. These results
establish the target on the measured GPU; they do not guarantee 20 B/sec on
every GPU or under every operating condition.

## Implementation and validation

The preceding arithmetic and report-processing optimizations are described in
the [2026-09-21 report](2026-09-21-frobenius-20b.md). This change selects a newer
compiler for that same implementation. The kernel still uses 91 registers per
thread, zero local bytes and 14,752 shared bytes per block.

The benchmark image `im-vZ6bOy9hMYSLXvtmTF7CiD` derives from the frozen CUDA 13.3
image `im-LEaik53IOCmWvHm1O2UUPQ` with `cuda-nvcc-13-4` and
`cuda-cudart-dev-13-4` installed at package version `13.4.92-1` alongside 13.3.
The validator records the compiler version separately for each build and selects
it by absolute path. Candidate binary SHA-256:
`f9d1bbc5f0da880f96ff7ca50a8664575239925089b84860a65c0a72c6514cfc`.

All ten timing samples reproduce 705 sorted DP32 reports, zero drops, and SHA-256
`530de6e2e95f910cb8ce89e9db3ad681917296817650c4a5a5492d75e6d18e4e`.
The full GPU arithmetic/storage/shared-mask suite passes. The 17 compatibility
cases cover complete and partial blocks, worker counts 640/641/256, DP weights
0/50, odd launch lengths 1/3/17, and a 4,097-step launch crossing the iteration
guard. Checkpoint images and both resume directions match byte-for-byte.
The walk ID, DP32 predicate, checkpoint v2 and `gpu-packed32` format are preserved.

The [build-target check](2026-09-22-frobenius-20b-target-check.json) also passes
`make check-frobenius32-20b-gpu` using the committed Make recipe and production
flags. It rebuilds the runner and all three GPU test binaries with CUDA 13.4,
then runs the client fixtures. Local `make check-cli` passes.

## Reproduction

With CUDA 13.4.92 installed at `/usr/local/cuda-13.4`:

```sh
make gpu-frobenius32-20b
make check-frobenius32-20b-gpu
```

For another installation location, pass
`FROBENIUS_20B_NVCC=/path/to/cuda-13.4/bin/nvcc` to both commands.
The ordinary production target continues to use the caller's `NVCC` setting;
the new target selects the measured compiler explicitly. No fleet is redeployed
by these targets or this PR.

To repeat the direct compiler comparison in the frozen benchmark environment:

```sh
modal run validate_frobenius_20b.py --control v6 --mode confirm \
  --selected production_onb \
  --output research/production/frobenius-20b-cuda134-recheck.json
```

The default `--control v3` compares the entire current profile with v3 built
using CUDA 13.3. To reproduce the preceding inverse-network comparison alone,
use `--control v5 --selected production_cuda133`.

## Other experiments

The [scheduling screen](2026-09-22-frobenius-20b-overlap-screen.json) found that
moving x-coordinate conversion ahead of y-coordinate reduction reduced the
median paired rate by 0.230795%. Moving denominator preparation there as well
reduced it by 7.760720%. Both matched the frozen corpus; neither is promoted.
The queued paired-product experiment was cancelled before GPU execution once
the compiler comparison had exceeded the target in all five samples.
