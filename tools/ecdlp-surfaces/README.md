# Elliptic-curve surface searches in Rust

A dependency-free Rust project with four command-line tools for quadric-pencil
classification and subgroup-transfer checks. It supports small odd-prime
fields and the two pinned Koblitz fixtures over GF(2^83). Requires Rust 1.70 or newer.

Agents can invoke `$ecdlp-surfaces` or read the
[ecdlp-surfaces skill](../../.agents/skills/ecdlp-surfaces/SKILL.md) for when to
use each command, input requirements, reproducible examples, and output limits.

## Build and run

From the repository root, change into `tools/ecdlp-surfaces` first.

```sh
cd tools/ecdlp-surfaces
cargo build --release --offline
cargo test --offline

cargo run --release --offline --bin surface_search -- --output examples/surface_candidates.json
cargo run --release --offline --bin transfer_check -- --scalar 37 --output examples/transfer_certificate.json
cargo run --release --offline --bin frobenius_filter -- --output examples/frobenius_result.json
```

Each executable also accepts `--help`. Omit `--output` to print JSON to stdout.
Negative integers work as either `--a -1` or `--a=-1`.

## 1. Find containing quadric surfaces

```sh
cargo run --release --offline --bin surface_search -- \
  --prime 101 --a 1 --b 46 --scalar 37
```

The default source is `y^2 = x^3 + x + 46` over F_101, with 109 rational points.
The program selects a generator of its largest prime subgroup and constructs
the demonstration point Q = 37P. It returns P = (2,37), Q = (64,19), and
101 smooth quadrics, of which 54 are split over F_101.

For a general nonsingular short Weierstrass curve, use the embedding

```text
(x,y) -> [W:X:Y:Z] = [1:x:y:x^2]
origin -> [0:0:0:1]

Q1 = WZ - X^2
Q2 = Y^2 - XZ - aWX - bW^2
S_lambda: Q2 + lambda*Q1 = 0
```

The intersection Q1 = Q2 = 0 is the elliptic curve. Every S_lambda contains it.
The symmetric matrix determinant is `(lambda^3 + a*lambda + b)/4`, so smoothness
is an exact field calculation. A smooth member is split precisely when that
cubic value is a nonzero square: the quadric already has the rational point
[0:0:0:1]. The additional pencil parameter lambda = infinity gives the singular
quadric Q1 and is not among the finite candidates.

The elliptic group law exists on the curve's image. It is not a group law on all
points of a containing quadric. The report also gives the group-preserving
embedding P -> (P,O) into the abelian surface E x E, whose law is componentwise.

## 2. Check an ECDLP transfer

```sh
cargo run --release --offline --bin transfer_check -- \
  --prime 101 --a 1 --b 46 --r 109 \
  --p-point 2,37 --q-point 64,19
```

This does not need the discrete logarithm of Q. It checks that P has prime
order r, Q belongs to the cyclic subgroup generated by P, both points round-trip
through the quartic model, and the image of P retains order r. Membership is
checked by enumerating the small subgroup; the tool does not return its log.

If a scalar is already known for a demonstration, add `--scalar 37` to verify
Q = 37P explicitly. Use `--q-point O` for the origin. Coordinates are reduced
modulo the source field.

In the library, `Curve::image_add` and `Curve::image_multiply` implement the
transported law. `Curve::decode` accepts projectively scaled coordinates,
handles the origin, and rejects points that lie only on a containing surface.
Checking rQ = O alone is insufficient when the rational r-torsion has rank two;
the checker verifies actual membership in <P>.

## 3. Filter candidate abelian surfaces

```sh
cargo run --release --offline --bin frobenius_filter -- \
  --q 101 --trace=-7 --coeffs 14,251,1414,10201
```

`--coeffs c1,c2,c3,c4` represents the monic surface polynomial
`T^4+c1*T^3+c2*T^2+c3*T+c4`. The source polynomial is `T^2-trace*T+q`.
The tool computes exact quotient and remainder, checks the surface reciprocal
conditions, and checks that the quotient has the elliptic shape and Hasse bound.

A nonzero algebraic homomorphism E -> A over F_q, where A is an abelian surface,
requires the source factor in A's Frobenius polynomial. Passing this filter
does not construct that map, determine its kernel, certify subgroup preservation,
or establish that the supplied polynomial is realized by a variety. The caller
supplies an actual field size and a source trace; prime-power validity and all
Honda-Tate existence conditions are not checked.

For an incompatible example, the polynomial `(T^2+101)^2` is rejected:

```sh
cargo run --release --offline --bin frobenius_filter -- \
  --q 101 --trace=-7 --coeffs 0,202,0,10201
```

## 4. Check the binary n=83 Koblitz fixtures

From the repository root:

```sh
cargo run --release --offline --locked \
  --manifest-path tools/ecdlp-surfaces/Cargo.toml --bin binary_surface_check -- \
  --degree 83 --a both --output /tmp/n83-surfaces.json
```

Use `--a 0` or `--a 1` for one variant. The field is GF(2^83), represented by
`z^83+z^45+z^2+z+1`, and the source is `y^2+xy=x^3+a*x^2+1`. Generators,
subgroup orders, and cofactors are pinned to the cited repository fixtures.
Default targets are public demonstrations `Q=37P`. With a supplied
`--q-point 0xX,0xY` or `O`, select one variant and omit `--scalar` when the log
is unknown. Decimal coordinates also work; masks must fit the recorded basis.

The modulus is checked by Rabin's irreducibility criterion. The curve order
comes from the Koblitz Frobenius recurrence and is checked against `r*h`.
The existing Sage proof receipt supplies primality for the wide a=0 order;
a=1 also receives a fresh deterministic u64 check. The output distinguishes
reused proof evidence from checks performed in the current run.

In characteristic two the embedding still uses `[1:x:y:x^2]`, but its pencil is

```text
Q1 = WZ + X^2
Q2 = Y^2 + XY + XZ + aWZ + W^2
S_lambda = Q2 + lambda*Q1
```

Smooth finite members have `lambda != a`. Such a member is split exactly when
`Tr(lambda+1/(lambda+a)^2)=0`. There are `2^83-1` smooth finite members, and
`(#E-2)/2` of them are split. These are algebraic counts, not a scan of the
field. The finite member `lambda=a` and the member at infinity are singular.

The checker verifies subgroup membership without enumeration using the cited
prime r, `#E=r*h`, and `gcd(r,h)=1`. It checks round trips over the Frobenius
orbits, projective scaling, transported addition, and a surface-only rejection
control. It describes inclusion into `E x E` and into the mixed `E_0 x E_1`,
using the matching component in each case, and rejects the opposite
product `E_(1-a) x E_(1-a)` over the same field: the Frobenius factors differ
and the source prime does not divide the target elliptic order.

Large exact integers are JSON decimal strings; field elements are hexadecimal
coefficient masks. The separate general `frobenius_filter` retains its u64/i128
limits and is not run at q=2^83. The binary CLI has fixed n=83 presets; it is
not a general binary-curve or arbitrary abelian-surface-map constructor.

The [n=83 study protocol](../../research/ecdlp_surfaces_n83_20261012/PROTOCOL.md)
binds the source fixtures and verification scope.

## Repository checks

Run `./check.sh` from this directory or from the repository root. It checks
formatting, release tests, Clippy, all four binaries, and byte-for-byte
reproduction of their committed examples. CI runs the same checks.
The [integration report](../../docs/ecdlp-surfaces/REPORT.md) contains the
explanatory diagram, PDF, exact inputs, and evidence boundaries.

## Scope and verification

The odd-prime point arithmetic and enumeration support 3 < p <= 10,000.
This matches the small-field Python prototype. Arithmetic uses u64/u128;
the polynomial filter uses checked i128 arithmetic and q <= i64::MAX.
The binary checker uses bounded u128 arithmetic for the pinned n=83 fixtures.
These are mathematical demonstration tools with variable-time arithmetic;
general cryptographic-curve and secret-key implementations are not supplied.
Equivalent embeddings preserve the same ECDLP; no faster solver is supplied.

Tests cover the independently checked default scalar multiple, identity and
two-torsion cases, projective scaling, group identities, rejection of points
outside the cyclic subgroup, matrix determinants, and compatible/incompatible
Frobenius polynomials. Generated example JSON files are included.
