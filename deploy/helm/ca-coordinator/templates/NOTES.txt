Three things worth knowing before you rely on this:

  1. The coordinator is a rendezvous, not an authority.  It assigns no
     work and stores nothing the agents cannot rebuild, so losing the pod
     loses no work: agents keep walking their claimed units and
     reconverge when it comes back.
  2. It runs as exactly one replica on purpose.  Two would each hold half
     the distinguished-point table and miss every collision that spans
     them, which is the one thing the shared table is for.
  3. Agents open every connection.  Nothing needs to reach *them*, which
     is why they can sit on spot capacity, behind NAT, or in a namespace
     that allows no inbound traffic at all (networkPolicy.enabled=true
     writes that down).
{{- if not .Values.coordinator.persistence.enabled }}

Progress is held in memory.  A restart re-learns it from the agents'
next check-ins, which costs a few seconds and no work; set
coordinator.persistence.enabled=true to have a replacement pod start
from where the last one stopped instead.
{{- end }}
