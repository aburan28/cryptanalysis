# Preregistered n37/n41/n53 cold full-rank control

Question: on one frozen public target per field, how much does the existing exact-support four-summand IC pipeline charge to build a fresh base, support index and full-rank factor-log table before its online target recovery? This is a correctness and stage-cost control for the ECC2K-130 feasibility goal, not an ECC2K-130 attack claim.

`CONFIG.json` freezes the three seeds, producer commit and source digests, pair-index policy, one precomputation fixture plus exactly one primary target, order n37→n41→n53, time limits and 16 GiB resource cap before any new target is generated. The source commit matches the published 2026-10-02 n41/n53 online receipts by source digest. Build the two Rust examples from that exact commit, with no uncommitted sibling-repository changes. Direct arguments are `n 0 eta_num eta_den direct_seed signed_expanded independent query_mode 2`, with `KIC_SHARED_FACTOR_LOG_PRECOMPUTATION=1`; rho arguments are `n 0 signed_frobenius 1 packed rho_seed`, with `KIC_RHO_FIXED_TARGET_SCALAR` set from direct fixture 1 after direct completes. The published scalar is a fixture and replay sidecar, never an input to the IC collector. The direct first fixture builds the reusable factor logs; the second fixture is the sole primary target. No unsuccessful seed may be replaced.

Keep raw JSONL, stderr, exit/resource receipts, executable and input hashes, and an independent group replay of both scalars and a checked relation sample for every rung. Compute the primary online interval only from the producer's five exclusive fixture-1 phases and compare it with rho's first-walk-to-replay interval on exactly the same Q. Compute cold one-target cost separately from curve setup, factor base, pair index, all fixture-0 rank/log/verification work, and fixture-1 target work. Exclude process launch, input load and scalar-derived point generation from both comparable intervals; report process wall separately. The producer's `charged_total_ms` omits some validation phases, so it is not the cold total. A missing stage or failed replay leaves speedup null.

The host has no auditable isolated-CPU receipt; all CPU times and ratios are exploratory. Do not promote a controlled speedup or extrapolate to n131. Full candidate IDs require exact point-set digests and completed manifests; keep `candidate_id: null` if those are missing. Freeze raw failures and zero-yield outcomes. A successful full-rank recovery at a toy n is an algorithmic control only. The next selection decision must consider factor-base size, folded columns, rank per query, memory, and cold-to-online setup dominance, not only SAT/PDP latency.

The sibling crate does not track `Cargo.lock`; `producer-Cargo.lock` is frozen here with SHA-256 `f6e3447b98a81f515b4a73deb59bdc0fe39dae6046be0fe9a0b111d25e76e7b6`. Build with this lockfile and `cargo build --locked --release --example koblitz_rank_fixture --example koblitz_rho_fixture`.

RSS preflight: Darwin rejected `RLIMIT_AS` even for a `/usr/bin/true` child. The runner therefore samples the child RSS every 100 ms via `/bin/ps`, kills on >16 GiB, fails closed if polling fails, and records the per-child `wait4` peak. The run remains an exploratory unisolated-host measurement; the RSS sampler is outside the producer's internal phase intervals.
