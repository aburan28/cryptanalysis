# A1 all-hit conjugate-x filter: frozen paired experiment

The collector's full 735,000-orbit index is the authority for each pair
lookup. The candidate builds a distinct raw-x Bloom filter from **every**
loaded index key and all 53 Frobenius conjugates, checking every insertion
before collection. On a negative, it skips the 53-squaring orbit-key
calculation; on a positive, the original canonicalization, exact map lookup,
ordered witness verification, weighted row, and rank update run unchanged.
The filter is opt-in through `A1_CONJUGATE_BLOOM=1`.

Freeze two full-index query streams: the historical `primary.json` with
2048 previously frozen queries, and `disjoint.json` generated by
`make_disjoint.py` with Python Random seed 20261109. The second stream has
2048 unique scalar queries disjoint from the primary stream. Both use the
same curve, exact 735,000-orbit index, 12,720-point base, and rank-five stop
criterion. These are relation-preparation workloads with zero target count.
All candidate/reference pairs run the same binary and input bytes, toggling
only the environment variable. Order: primary off/on, disjoint on/off.

Before treating a pair as correct, require equal ordered `relation_events`,
query count, 15-ish raw incidence sequence, distinct weighted rows, rank,
and base points checked. The Rust program independently replays every
weighted row as a point equality. The reference and candidate must have
equal nonidentity difference and exact-hit counts; the candidate must obey
`nonidentity = Bloom negative + Bloom positive` and
`orbit keys = Bloom positive`. All negative probes are safe because each
index key's entire Frobenius orbit was inserted and then exhaustively
checked. Bloom positives still use the exact pair map.

Measure the operation reduction as paired reference orbit-key computations
minus candidate computations, divided by reference computations. Record
reusable build and exhaustive-check wall time and filter bytes separately
from collection online time. Keep every query phase in its existing timing
bucket. CPU wall-time ratios from this host remain exploratory until the
repository's host-level isolation gate is satisfied. A relation-collection
stage result does not substitute for a one-target IC versus rho comparison.
