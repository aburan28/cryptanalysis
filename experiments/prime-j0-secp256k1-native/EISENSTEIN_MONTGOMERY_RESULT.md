# Eisenstein Montgomery field representation for secp256k1

The secp256k1 prime field admits a two-coordinate representation in which
the curve's cube-root-of-unity action is a linear map. An exact reference
implementation verifies the representation, Montgomery reduction, and
endomorphism constants on 10,144 field multiplication pairs. This creates a
specific native-kernel experiment for the tau and rho scalar paths: replace
repeated multiplication by the large field constant beta with coefficient
swaps, additions, and sign changes, then measure the complete point operation.

## Representation and arithmetic

Let `omega^2 + omega + 1 = 0`, `R = 2^128`, and
`p = 2^256 - 2^32 - 977`. The field root used by the secp256k1 endomorphism is

```
beta = 0x7ae96a2b657c07106e64479eac3434e99cf0497512f58995c1396c28719501ee
pi   = -367917413016453100223835821029139468249
       -64502973549206556628585045361533709078 * omega
```

Direct integer checks give `N(pi) = p`, `pi(beta) = 0 (mod p)`, and
`beta^2 + beta + 1 = 0 (mod p)`. Hence `Z[omega]/(pi)` maps to `Fp` by
`a + b*omega -> a + b*beta (mod p)`. The reference keeps the Montgomery
residue `x*R (mod pi)` as a balanced pair `(a,b)`. For such a pair,

```
omega(a,b)       = (-b, a-b)
(1-omega)(a,b)   = (a+b, 2*b-a)
N(a,b)           = a*a - a*b + b*b
```

The first map preserves the norm and needs no normalization. The second is
the tau constant action and may require normalization. Ring multiplication
uses three variable-width integer products via Karatsuba. Ring Montgomery
reduction chooses `q = -z*pi^{-1} (mod R)`, divides `(z+q*pi)` coefficientwise
by `R`, and balances the result modulo `pi`. Its naive implementation has
**three ring products, or nine approximately 128-bit integer products** per
field multiplication; six products have fixed constants and the inverse
product only needs its low 128 bits. This operation count is a construction
description, not a performance result.

The triangular lattice generated by `pi` has covering radius `sqrt(p/3)`.
Nearest-lattice balancing therefore gives `N(a,b) <= p/3` and
`|a|, |b| <= 2*sqrt(p)/3 < R`. For a product of balanced inputs,
`|z| <= p/3`; since `q` has both coefficients in `[0,R)`, `|q| <= R`.
The unbalanced Montgomery quotient `u=(z+q*pi)/R` consequently satisfies
`|u| < p/(3R) + sqrt(p) < 4R/3`. Thus each quotient coefficient has
absolute value below `8R/(3*sqrt(3)) < 2R`. A nearest-lattice correction
`c` has `|c| < 4/3 + 1/sqrt(3)`, so its integer Eisenstein norm is in
`{0,1,3}`. A native implementation can inspect a fixed set of 13
corrections rather than use arbitrary-precision division in its hot path.
This bound does not imply that only the four corrections seen in the sample
can occur.

## Exact reference check

Run `python3 experiments/prime-j0-secp256k1-native/eisenstein_montgomery.py`.
The fixed seed is `20261008`. The reference checked 144 edge pairs and
10,000 random pairs, including encode/decode, multiplication, addition,
subtraction, threefold omega action, the tau constant, and every Montgomery
cancellation. All checks passed. The largest balanced coefficient occupied
128 bits; the largest post-reduction coefficient before balancing occupied
129 bits. The observed balance corrections were `(0,0):3349`,
`(0,1):1657`, `(1,0):1665`, and `(1,1):3473`. The reference source SHA-256
for this check was
`bddf4dbe8a5490fad1a6a78aaa569dbd00715aabde895e92b6ec170a1c7a0041`.

The next experiment is a fixed-width portable C or Rust kernel with exact
replay against this reference, followed by complete Jacobian tau/rho and
single-scalar measurements on an isolated physical CPU. Conversion,
normalization, and all field operations must be charged to the point result.
The Python reference establishes identities and bounds; it does not give a
CPU timing ratio.
