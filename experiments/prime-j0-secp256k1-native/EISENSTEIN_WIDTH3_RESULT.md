# Three-orbit width-three tau scalar path

The native secp256k1 evaluator now uses a width-three `tau` digit set
assembled from three six-point unit orbits. On the frozen 86-scalar
generator workload, it replaces 4,420 width-two mixed additions with
1,040 mixed and 2,085 cached-projective additions. Its charged
field-product proxy falls from **104,305 to 98,117**, a saving of
**6,188 products (5.93%)** after charging seed preparation for every
scalar. Independent affine replay verified both paths on the 86 frozen
scalars and 128 additional deterministic random scalars: 428 exact
outputs in all. These are operation counts and correctness results;
isolated full-operation wall time remains to be measured.

## Digit construction and termination

Write `tau=1-omega`, `tau^2=3tau-3`, and
`N(a+b tau)=a^2+3ab+3b^2`. The ideal generated by `tau^3` is
`9 Z + 3 tau Z`: multiplication by `tau^3=-9+6tau` and then by
`tau` gives generators `(-9,6)` and `(-18,9)`, whose determinant has
absolute value 27. Consequently, a residue modulo `tau^3` is
specified by `(a mod 9,b mod 3)`. Exactly 18 of the 27 classes have
`a` nonzero modulo 3.

The digit set is `0` and `+/- omega^j u` for `j=0,1,2` and
`u` in `{1,2,1+tau}`. The 18 nonzero digits occupy the 18 required
residue classes exactly once. Subtract the matching digit, divide by
`tau`, and repeat. Since a nonzero digit makes the remainder divisible
by `tau^3`, the next two digits are zero. A state that equals a digit
becomes the terminal accumulator seed.

Every digit has norm at most seven. The norm triangle inequality gives
`N((z-d)/tau) <= (sqrt(N(z))+sqrt(7))^2/3 < N(z)` for `N(z)>=14`.
For the 55 ring elements with norm at most 13, the exact residue map
reaches zero or a digit in at most three transitions; every successor
in that finite set has norm at most nine. Thus the recoder terminates
for every Eisenstein integer. The Rust test reconstructs all 6,561
pairs in `[-40,40]^2` and checks the width-three sparsity condition.

## Point path and charged operations

The base orbits are `G`, `2G`, and `(1+tau)G=(2-omega)G`.
One doubling prepares `2G`; one mixed addition with `-omega G`
prepares the third base. The two projective bases keep cached `Z^2`
and `Z^3`. Applying `omega` changes the X coordinate, so each base
supplies its three signed orbit points without more point additions.
The unit orbit uses the 11-product mixed formula. The other two use
the 14-product cached-projective formula, including equal/inverse
point handling. A `tau` step uses five raw field products.

The proxy charges per scalar `7+11+4=22` field products for the
doubling, mixed addition, and two Z caches. It also charges every
`tau` step and digit addition in the frozen interval:

| Path | Tau steps | Mixed additions | Cached additions | Per-case setup | Field-product proxy |
| --- | ---: | ---: | ---: | ---: | ---: |
| Unit width two | 11,137 | 4,420 | 0 | 0 | 104,305 |
| Three-orbit width three | 11,119 | 1,040 | 2,085 | 22 | 98,117 |

This proxy counts calls to field multiplication or squaring in the
point formulas. It does not count integer recoding, `omega` coordinate
balancing, field-representation normalization work inside a product,
affine inversion, or output conversion. Those costs remain inside
both complete-operation benchmark commands and can decide CPU speed.
The projective seeds are rebuilt for each scalar, including the first
one in each process. The implementation is variable time and intended
for public scalars.

## Reproduction

From this directory:

```sh
cargo build --release --bin eisenstein_fixed
cargo test --release --bin eisenstein_fixed
PYTHONDONTWRITEBYTECODE=1 python3 check_eisenstein_width3.py
```

The complete-operation commands are
`eisenstein_fixed --benchmark-scalar-w2-case FIXTURE INDEX` and
`eisenstein_fixed --benchmark-scalar-w3-case FIXTURE INDEX`.
Their `--check-` counterparts emit the same verified affine point
without a timing field. A controlled CPU ratio requires the
[isolated host receipt](../../docs/ISOLATED_BENCHMARKS.md).

Build the binary on that Linux host and generate the paired manifest
there, substituting its verified CPU partition and NUMA node:

```sh
python3 make_eisenstein_width3_manifest.py \
  --repo-root /workspace/cryptanalysis \
  --binary /workspace/cryptanalysis/experiments/prime-j0-secp256k1-native/target/release/eisenstein_fixed \
  --cgroup /sys/fs/cgroup/benchmark-isolated \
  --cpus 4-5 --execution-cpu 4 --mem-node 0 \
  --output /workspace/isolated-bench/eisenstein-width3.json
python3 /workspace/cryptanalysis/scripts/isolated_bench.py probe /workspace/isolated-bench/eisenstein-width3.json
python3 /workspace/cryptanalysis/scripts/isolated_bench.py --queue-root /workspace/isolated-bench submit /workspace/isolated-bench/eisenstein-width3.json
```

The manifest hashes the exact executable and source artifacts, pairs
both arms on every frozen scalar and point, and requests five serial
repetitions per case. The CPU IDs in the command are examples; the
runner rejects a host that lacks their exclusive isolation evidence.
