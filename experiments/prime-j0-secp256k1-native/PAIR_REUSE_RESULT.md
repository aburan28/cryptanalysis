# One-use adjacent τ-digit pair dictionary: low reuse

The [screen source and protocol](PAIR_REUSE_PROTOCOL.md) were frozen in
`3b3c7c16` before this retrospective run on the existing 64-case native
fixture.  The screen reconstructed every saved short coefficient pair
from its digit stream and verified that the 64 input bases are distinct.
The [raw row record](pair-reuse-result.json) contains both offsets for
every case, gap histograms, source/dependency/fixture SHA-256 values,
and null CPU and novelty claims.  It regenerated byte-for-byte.

| Disjoint adjacent pairing | Pair uses | Distinct pair orbits within each base | Repeated uses | Existing nine-seed hits |
| --- | ---: | ---: | ---: | ---: |
| Start at highest digit | 1,145 | 1,140 | 5 | 0 |
| Skip highest digit | 1,114 | 1,104 | 10 | 0 |

Even allowing each base to choose whichever of those two pairings has
more repetition yields only **15 repeated uses** across all 64 bases.
No pair orbit repeats more than twice within a base.  If forming a pair
point cost exactly one same-cost addition and all τ shifts were free,
the most that reuse could save is **15 additions**, or **210 `M+S`** at
14 units per addition.  That is only 0.24% of the frozen path's 88,656
units; actual pair construction, table access, and scalar-side selection
would add cost.  No existing seed orbit supplies a free pair point.

This rejects **this two-offset, disjoint adjacent-pair dictionary** as
a worthwhile one-use implementation target in the stated source-count
model.  It does not rule out a new fused addition formula, different
digit alphabet, different pairing policy, repeated-base workload, or a
CPU result.  It makes no academic novelty or controlled speed claim.
