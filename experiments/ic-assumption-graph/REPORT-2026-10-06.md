Claim labels used below: **[proved]** (theorem or per-instance check),
**[derived]** (follows from cited proved results),
**[measured]** (toy-curve measurement in a frozen receipt),

## 1. Question, scope, method

**Question.** Which algorithms comprise index calculus (IC) for the elliptic-curve
discrete logarithm problem (ECDLP), and which assumptions does each algorithm rest on?

**Scope.** The seven IC stages in `AGENTS.md` (setup, factor base, point
decomposition, relation collection, relation linear algebra, target descent,
verification) plus optional isogeny transport and the paired Pollard-rho
baseline. Both binary-extension curves (Koblitz and subfield families, including
ECC2K-130) and prime-field curves (generic, `j = 0`, `j = 1728`, tower bases)
are covered. The graph names concrete algorithm families, not one frozen
candidate: no `IC1...` ID is issued here (`candidate_id: null`), no factor-base
count is inferred, and no speedup is claimed.

**Method.** Survey of this repository's IC docs, experiments, and code, plus the
sibling `crypto` study repository's frozen IC notes where this repo points to
them, and the classic IC/isogeny literature those files cite. Repo sources below
were read in full; literature entries carry a `source_read` note following
`experiments/ecc2k130-isogeny-class/sweeps/literature/citations.json`
(`full text` / `abstract` / `metadata`; `metadata` means the claim is recalled
and flagged, not verified here). Negative and inconclusive findings are kept:
Sections 5 and 7 list what failed, what is open, and what was checked.

## 3. Stage by stage: algorithms and their assumptions

### 3.1 SETUP: exact instance

- **Exact field / curve / subgroup / encoding** (white box). Binds the field
  representation, defining modulus, Weierstrass model, subgroup order `r`,
  cofactor, generator `G`, and element encoding before anything is timed.
  - **A-SETUP1 [proved]:** the `EC1...h...` curve ID is SHA-256 over the
    canonical `{"field": ..., "curve": ...}` record (sorted-key compact JSON),
    excluding the ID itself and any run data (`AGENTS.md`; `curves.yaml`
    `identity_rule`). Alias and route metadata never change the ID.
  - **A-SETUP2 [proved]:** cofactor clearing maps any curve point into the
    prime-order subgroup `G` generates; subgroup membership is then exact
    (`suite/docs/ic/README.md` § subfield curves; `pdp-degree-heuristics`
    usable-point rule).

### 3.2 FB: factor-base construction

- **F2-subspace base** (`prefix` / `geometric`): `F_V = {P : x(P) in V}` for an
  `l`-dimensional subspace `V`, e.g. `span{1,z,...,z^(l-1)}`
  (`experiments/pdp-degree-heuristics/README.md` §2).
  - **A-FB1 [proved]:** for prime `n`, `dim V^(2) >= 2l-1`, and below `n-1`
    only geometric progressions `c*span{1,g,...,g^(l-1)}` attain it (Hou-Leung-
    Xiang field Kneser; Bachoc-Serra-Zemor field Vosper; cited and applied in
    `pdp-degree-heuristics` §3 and `linearized-half-decomposition`).
    Consequence **[derived]**: progressions minimize the product profile and
    hence the PDP unknown count.
  - **A-FB2 [heuristic + measured]:** a random abscissa lifts with probability
    about one half and a lifted point lands in `<G>` with probability about
    one half (cofactor and trace dependent). Receipts record usable `B`,
    geometric count, strict-subgroup count, and folded columns separately;
    `B` is never inferred from `l` (`AGENTS.md`; `pdp-degree-heuristics` §2).
- **Trace-zero base** (`geomtrace`, `kertrace`): `V` inside `ker Tr`.
  - **A-FB4 [proved]:** on `y^2+xy=x^3+b`, every point of the odd-order
    subgroup is a double, so `V subset ker Tr` puts the base in `2E` and
    doubles the yield at the same degree (except near excess zero where the
    vacuous trace row costs one degree; `pdp-degree-heuristics` §§4-5,8;
    `fb-search/PRIOR_ART.md` via Kosters-Yeo).
- **Automorphism-orbit base** (prime fields): whole `Aut` orbits
  (`{+-1}`, `mu4`, `mu6`) so `w*m` points carry `m` unknowns
  (`suite/docs/ic/README.md` § prime-field curves).
  - **A-FB3 [proved with per-instance checks]:** `psi(G) = [lambda]G` is
    checked on the subgroup point (sign branch fixed empirically), and orbit
    folding preserves the relation lattice only with that check plus cofactor
    handling (`docs/ALGORITHMS.md` § GLV; `suite/docs/ic/README.md`). The older
    `j=0` module kept representatives but discarded non-representative images,
    so its orbits added size without coverage **[measured]** (8.6x vs 8.7x
    predicted after the fix).
- **Tower base** (prime, Petit-Kosters-Messeng): algebraic factor base over an
  extension tower (`suite/docs/ic/FRAMEWORK.md` §8).
  - Coverage is a **heuristic** (A-FB2 family); the solver-axis test that would
    decide whether to build the oracle end to end is open (pilot FFD flat,
    round-2 slow rise; no oracle built).
- **Random subgroup base**: pseudo-random abscissae, keep `[h]P`.
  - Rests on A-FB2 only; needs no linear structure, so it suits the
    pair-table oracle and is refused by Gröbner/SAT oracles that need a
    subspace (`suite/docs/ic/README.md` § choosing a base).

### 3.3 PDP_m: point decomposition

Given `R`, return `m` base points summing to it (or `None`). Every returned
decomposition is re-added in the group before it becomes a relation
(`suite/docs/ic/README.md`).

- **Semaev summation polynomials** `S_{m+1}` (plus symmetrized / chained-S3
  forms; Semaev 2004 [metadata]; Faugère-Huot-Joux-Renault-Vitse 2014
  [metadata]; Shantz-Teske 2013 [metadata]).
  - **A-PDP1 [proved]:** `S_{m+1}(x1,...,xm,xR)=0` iff the corresponding points
    sum to `R` up to sign (Semaev; repo re-verifies by re-addition and by
    exhaustive cross-checks, e.g. `pdp-degree-heuristics` §9: 73,528/73,528
    oracle agreements).
- **Weil descent** to an MQ/Boolean system (binary) or `Fp` system (prime).
  - **A-PDP2 [proved with checks]:** descent is sound, but solutions name
    abscissae over the algebraic closure: lifts can fail (twist points) or hit
    `x=0` (2-torsion). Receipts count `lift_failures` and
    `unliftable_systems` apart from `did not decompose`
    (`suite/docs/ic/FRAMEWORK.md` §3; `volcano-ic` § results: 146/29k spurious
    `x=0` solutions, no twist solutions there).
  - Yield=Integer models: **A-PDP3 [heuristic + measured]:**
    `P(decomposable)` from `|F|^m/(m! r)` or the `psi`-class count `T_psi/r`
    plus a Poisson/birthday step. The naive `|F|^m/#E` is off by up to 2.2x;
    the `psi`-class mean is exact for `m=2` and the Poisson step lands within
    2-3% (`pdp-degree-heuristics` §5); volcano-ic birthday model within 0.0046
    (`experiments/volcano-ic/README.md`).
- **Pair-table / MITM oracle** (meet in the middle over pair sums; `m=2..4`).
  - Rests on A-PDP3 for yield; cost is exact table work (`|F|^2/2` pairs,
    folded variants) plus lookups. It is the reference row algebraic oracles
    must beat (`suite/docs/ic/FRAMEWORK.md` §4).
- **Gröbner family** (Buchberger, F4/F5, Matrix-F4/F5, MutantXL/MXL, XL,
  Crossbred; Faugère 1999/2002 [metadata]; Joux-Vitse [metadata]).
  - **A-PDP4 [refuted as stated]:** the Petit-Quisquater first-fall-degree
    assumption that solving degree tracks FFD with `O(log n)` growth
    (Petit-Quisquater 2012 [metadata/abstract]). Counter-evidence: Galbraith-
    Gebregiyorgis 2014 [metadata], Huang-Kosters-Yeo 2015 [metadata],
    Kosters-Yeo 2015 [metadata], and repo measurements (FFD 2 for all `m=2`
    and 3 for all `m=3` toy systems while solving degree diverges;
    `crypto/research/notes/index-calculus/RESEARCH_IC_BOUNDARY_LEDGER.md`
    §§5,14-17; `pdp-degree-heuristics` §5: FFD is the base degree for 95% of
    queries whatever the base).
  - **A-PDP5 [refuted as a cost proxy]:** the semi-regular (Bardet-Faugère-
    Salvy) `D_reg` predicts Gröbner cost. For two-summand Weil systems the
    homogeneous `D_reg` is exactly `l+1` (bilinear block structure) while
    `D_solve` is 2-4; the prediction misses by 0.5-1.2 degrees on average
    (`pdp-degree-heuristics` §§4-5). The structure-only excess rule
    `D = 2+[e<-3.5]+[e<-8.5]` (MAE 0.06, leave-one-`n`-out 0.08) replaces it
    for `m=2` **[measured]**.
  - **A-PDP6 [open]:** last-fall-degree bounds cost (Huang-Kiltz-Petit 2015
    [metadata]). No repo implementation establishes it as a predictor.
- **SAT / CDCL / WDSat** (Trimoska-Ionica-Dequen 2019 [metadata]).
  - **A-PDP7 [open]:** descended CNF-XOR scales past Gröbner. Measured on the
    same systems, CryptoMiniSat gains only ~10% from the product profile where
    Gröbner gains 10-100x (`pdp-degree-heuristics` §5); normal-basis weight-3
    SAT works but costs ~14 CPU-s per call dominated by UNSAT proofs
    (`volcano-ic` tau section). No theoretical bound is claimed.
- **Linearized half-trace oracle** (`PDP2ht`; Courtois 2016 [abstract read];
  Karabina 2015 [abstract read]).
  - **A-PDP8 [proved]:** `S_3` is `F2`-linear in `(e1,e2)`, so two-point PDP
    over `V` is an `n x (3l-1)` linear system plus half-trace splits
    (`experiments/linearized-half-decomposition/README.md`). Exactness checked
    against brute force (300/300 targets, 0 mismatches) **[measured]**.
    Needs `3l-1 <= n` (A-FB1) and `4l >= n+log2(4!)` for four-point existence;
    beyond the linearization limit the search dimension is exactly
    `max(0, dim V+dim V^(2)-n-1+[V in ker Tr])` **[measured refinement]**
    (`fb-search/PRIOR_ART.md`, `ABOVE_LIMIT.md`).

### 3.4 RC: relation collection

- **Random sampling** (`[a]G+[b]Q` per trial, ~`3 log2 r` adds) and
  **r-adding walk** (one add per trial; Teske [metadata]).
  - **A-RC1 [heuristic + measured + guard]:** walk targets are treated as
    uniform, but two rows with the same factor-base part and different
    `(a,b)` pin the log by collision, not by relation (24.4% of unguarded
    two-summand runs end this way; 82% when walk segments share one jump
    table). The guard (one hash insert per target, priced as a lookup) is
    mandatory (`suite/docs/ic/README.md` § boundary ledger round 2).
  - Yield per trial rests on A-PDP3; stopping rests on rank (below).
- **Single / double large-prime variation** (Thomé, Gaudry-Thomé-Diem
  [metadata]).
  - **A-RC2 [heuristic + measured]:** leftovers meet with birthday probability
    and the large-prime graph connects. Prime-orbit runs learn ~`N` large-prime
    logs from `N` differences; descent then hits after ~`r/(w*L)` differences
    (`suite/docs/ic/README.md` § prime-field curves).
- **Rank accumulation.**
  - **A-RC3 / A-LA4 [heuristic with a proved systematic shortfall]:** `B+eps`
    relations are expected to give full rank, but on cofactor-4 curves a
    two-summand relation space has rank `C-1` unless the base holds a 4-torsion
    point or lies in `ker Tr` (class-in-`E/<G> ~= Z/4` kernel; `pdp-degree-
    heuristics` §7). Collectors must stop at the achievable rank (computed via
    `monitor.achievable_rank`), solve modulo the kernel, and verify by fresh
    descents **[measured: 36 collections, 108/108 descended logs verified]**.

### 3.5 LA: relation linear algebra

Matrix LA here is the final sparse relation-matrix solve, not a PDP Macaulay
reduction (which belongs to `PDP` per `AGENTS.md`).

- **Structured Gauss + filtering** (singleton/clique removal, Markowitz pivot;
  Odlyzko [metadata]).
  - **A-LA3 [proved]:** eliminations are recorded and back-substituted exactly
    (`suite/docs/ic/README.md` § linear algebra).
- **Block Wiedemann / Lanczos** (Coppersmith, Kaltofen-Saunders, LaMacchia-
  Odlyzko [metadata]).
  - **A-LA1 [proved probabilistic]:** random projections and the Krylov +
    Berlekamp-Massey step succeed with the standard probabilistic guarantees,
    conditional on the field/modulus; reports carry core dimension, sequence
    length, and products.
- **Gain-graph** (1-/2-term relations): exact component-wise solve, every
  column certified by `[x]G == P` (`suite/docs/ic/README.md` § prime).
- **Modulus handling.**
  - **A-LA2 [proved]:** prime `r` solves directly; `p-1 = prod q^e` (classical
    `Fp*` IC) or composite `r` goes via Pohlig-Hellman per prime power plus
    Hensel lift and CRT, with every factor-base log verified before use
    (`docs/ALGORITHMS.md` § index calculus in `(Z/pZ)*`).
- Cost dominance **[measured]**: on `E(F_{p^3})` the relation phase grows as
  `n^{1/3}` but plain LA as `n^{0.68}`, so whole-method `S` bottoms near 200x
  rho and rises after; the double-large-prime variation grows as `n^{4/9}`
  with crossover past `2^230` (`suite/docs/ECDLP_ATTACK_MATRIX.md` §10b, citing
  the `crypto` residual-walks note).

### 3.6 TD: target descent and recovery

- **Direct recovery** (one relation over known column logs) and
  **recursive descent** (Joux-Lercier style [metadata]; GGM small-degree
  descent [metadata]).
  - **A-TD3 [heuristic]:** rerandomization `Q+[a]G` (uniform) or additive walk
    `Q+i[a0]G` covers the subgroup; the manifest records which
    (`AGENTS.md` `TDpdp`).
  - **A-TD1 [heuristic + measured]:** recursive subproblems are strictly
    smaller and terminate. Toy descents verify (e.g. `pdp-degree-heuristics`
    §7: 108/108; prime-orbit 64-target batches all recovered), but no general
    termination bound is claimed.
- **Learning database** (ordered descent adding verified differences).
  - **A-TD2 [proved with checks]:** a learned difference has known log only
    because `[d]G == Q` was checked; tampered/mismatched databases are
    rejected, never trusted (`suite/docs/ic/README.md` §§ logs/solve, prime).

### 3.7 ISO (optional): isogeny transport

`ISO1` requires an explicit verified map, ordered edge links, subgroup/log
transport, and charged route costs; anything less stays a proposal
(`AGENTS.md`). In characteristic two, degree-2 edges carry no ordinary `V2`
level label (`VOLCANO_NAMING.md`).

- **Vélu / sqrt-Vélu + volcano walk** (Vélu [metadata]; Kohel thesis
  [full text via citations.json]; Fouquet-Morain [metadata]; Sutherland
  [full text]; Bernstein-De Feo-Leroux-Smith sqrt-Vélu [abstract]).
  - **A-ISO1 [proved]:** ordinary components of the `l`-isogeny graph are
    `l`-volcanoes; depth is the `l`-adic conductor valuation; horizontal/
    descending counts follow Kohel/Sutherland.
  - **A-ISO2 [per-edge, checked]:** kernel rationality must be proved per
    edge. For ECC2K-130: degree-2 codomain is source-isomorphic (no new
    route), no rational degree-3 kernel exists, and degree 263 is the first
    prime degree with a new rational kernel **[measured/proved]** (small-
    isogeny gate + Sage replays;
    `experiments/ic-candidate-catalog/README.md` § isogeny links). The
    verified descending edge `e263d1_df508c4fc9a8` carries map, kernel, and
    subgroup-transport certificates.
  - **A-ISO3 [proved with checks]:** if `l` does not divide `r` (proved: source
    subgroup disjoint from kernel), `phi(G)` retains order `r` and
    `phi(Q)` is the image of the source target; dual/composition checks when
    available (`MEASUREMENT.md` § isogeny gate).
  - **A-ISO4 [conditional + blocked for ECC2K-130]:** Jao-Miller-Venkatesan
    GRH expander for horizontal walks [full text v3] plus smooth-conductor
    bridging. ECC2K-130's Frobenius conductor is `263 * 146505763881528721`
    with the 57-bit prime inert: any isogeny changing that part has degree
    divisible by it, and vertical navigation costs at least linear in `l`
    (Sutherland §3.3; Robert 2022 notes polynomial-in-`log l` vertical
    movement as open [full text]). Only the 262 curves one 263-isogeny down
    are reachable from `E0` (`experiments/volcano-ic/README.md`).
  - **A-ISO5 [proved]:** Vélu `O(l)` given the kernel; sqrt-Vélu `O~(sqrt l)`
    in the kernel's field of definition.

Volcano-ic consequence **[measured]**: at `n=19` (457-curve class modeling the
ECC2K-130 263-level), relation yield depends only on the factor base, not the
curve (eligible-pair identity on 457/457; birthday model within 0.0046);
`E0` needs 0.996x descendants' attempts (95% CI 0.976-1.017); formal `D_reg`
is 11 on all 1,371 sampled systems (bilinear minimum); 310/310 logs verified
(`experiments/volcano-ic/README.md`).

### 3.8 VERIFY and GOAL

- `VERIFY` checks `[k]G == Q` (and `[x]G == P` per column) before anything is
  called a result. A row without a verified answer is not a result
  (`AGENTS.md`; `crypto/AGENTS.md` §2). It reuses A-TD2 (learned logs) and,
  for `ISO1`, A-ISO3 (transport), hence the dashed links.
- `GOAL` is one verified target's online wall time paired with rho on the same
  point and resource envelope (`online_speedup = rho_online / IC_online`).
  Multi-target amortizations are secondary and never the headline
  (`AGENTS.md` measurement rules).

### 3.9 RHO baseline: what IC must beat

- **Teske r-adding walk + distinguished points** (van Oorschot-Wiener
  [metadata]; Teske [metadata]).
  - **A-BASE2 [heuristic + measured]:** the walk behaves as random;
    measured `S ~= 1.25` (whole-group prime order, one thread;
    `docs/ALGORITHMS.md`), `S ~= 1.3` in the study unit. Standard deviation
    of a single rho run is about half its mean.
- **Negation / automorphism fold** (Wiener-Zuccherato, Duursma-Gaudry-Morain,
  Gallant-Lambert-Vanstone [metadata]; Bernstein-Lange-Schwabe fruitless-cycle
  handling [metadata]).
  - **A-BASE1 [proved]:** no generic algorithm beats `Omega(sqrt(r/|Aut|))`
    (Shoup/Nechaev [metadata]); the fold is `sqrt(m)` (`sqrt 3 ~= 1.73` for
    `j=0` over the negation baseline, `sqrt 2 ~= 1.41` for `j=1728`;
    `sqrt(2n)` signed-Frobenius on Koblitz). The prime-orbit pipeline at
    28-40 bits spends 1.1-1.4x the folded batch-rho expectation **[measured]**:
    it is a generic algorithm with the automorphism oracle, not a
    subexponential step (`suite/docs/ic/README.md` § prime).
- **Precomputation rho** (Bernstein-Lange 2012/2013 [metadata]).
  - Fair online opponent for any IC online figure that excludes setup
    (`~l^(1/3)` online after `~l^(2/3)` precomputation); `fb-search` notes
    `m=2` subspace IC cannot beat it asymptotically (`PRIOR_ART.md`).
- **A-BASE3 [measured + pinned]:** everything is priced in group-addition
  equivalents per `sqrt(r)` (`S`), with native-to-`S` conversions pinned in
  `suite/docs/ic/calibration.json`. Per-run re-measurement drifted ratios by
  up to 3.7x and repriced identical work by up to 8% (round 4 fix;
  `suite/docs/ic/README.md` § boundary ledger).

## 4. Positive findings (what is solid)

1. The pipeline decomposes cleanly into stages with exclusive accounting; the
   graph's backbone (`SETUP` through `VERIFY`) matches `AGENTS.md`,
   `MEASUREMENT.md`, and `FRAMEWORK.md` with no missing stage. **[derived]**
2. Semaev correctness, Weil soundness (modulo lift checks), product-profile
   optimality, orbit folding (with checks), trace-zero doubling, linearized
   `S3`, structured-elimination soundness, Wiedemann/Lanczos probabilistic
   success, composite-modulus handling, learned-log correctness (with checks),
   volcano structure, Vélu costs, and the generic lower bound are all
   **[proved]** (theorem or per-instance certificate).
3. Smoothness/birthday yield, walk uniformity (with guard), large-prime
   matching, descent termination, rho random-walk behavior, and calibration
   stability are **[heuristic + measured]**: each has toy-curve receipts
   within a few percent or with explicit intervals, and each has a named guard
   or pin where the naive form fails.
4. The status split itself is a finding: of 32 assumptions in Figure 2, 16 are
   proved/checked, 11 are heuristic+measured, 2 are open, 2 are refuted as
   stated, and 1 is conditional (Section 6). The pipeline's weight rests on
   heuristics that have been measured, not on unexamined optimism.

## 5. Negative and inconclusive findings (what failed or stays open)

1. **FFD assumption [refuted as stated].** Petit-Quisquater-style claims that
   FFD bounds solving degree with slow growth do not hold uniformly
   (Galbraith-Gebregiyorgis, Huang-Kosters-Yeo, Kosters-Yeo; repo FFD 2/3 with
   diverging solving degree). Any subexponential claim resting on it alone is
   not currently believed (`suite/docs/ECDLP_ATTACK_MATRIX.md` §10).
2. **Semi-regular `D_reg` as a cost proxy [refuted].** Off by 0.5-1.2 degrees
   on Weil systems; homogeneous `D_reg = l+1` while `D_solve = 2-4`. The
   excess rule replaces it for `m=2`; `m>=3` degree prediction at scale stays
   **[open]** (`pdp-degree-heuristics` §§5,8-9).
3. **`m=2` subspace IC cannot beat generic rho with precomputation
   asymptotically [derived + measured].** Linearization caps the total at
   `2^(2n/3)` (~30 bits above rho at `n=131`) and the online cost at `~2^(n/3)`,
   the Bernstein-Lange exponent (`linearized-half-decomposition`,
   `fb-search/PRIOR_ART.md`). Below that needs a non-subspace base or a
   non-linearized oracle.
4. **Prime-field 2-decomposition IC is `O(p^{3/2})`, worse than rho [measured].**
   Test curve `y^2=x^3+x+19 (mod 271)`: both recover the log; rho ~21 ops, IC
   thousands of trials x 16 relations, exactly as predicted
   (`suite/docs/ECDLP_ATTACK_MATRIX.md` § IC).
5. **Gaudry-cubic whole-method never beats rho [measured].** Relation phase
   `n^{1/3}` but LA `n^{0.68}`; `S` bottoms near 200x rho around `2^50` and
   rises; double-large-prime crossover past `2^230`.
6. **ECC2K-130 isogeny escape is blocked [proved obstruction + measured].**
   Degree-2 isomorphic, no degree-3 rational kernel, first new degree 263;
   the 57-bit inert conductor prime forces any route changing it to have
   degree divisible by it; vertical `l`-isogeny costs at least linear in `l`.
   The 263-level adds a verified route, not an `IC1` candidate (no base, PDP,
   matrix, target, or paired rho there).
7. **Inconclusive / open:** last-fall-degree as a predictor, SAT scaling past
   Gröbner at scale, tower-oracle `m>=4` (out of memory at `N=16`, only `D>=7`),
   `m>=3` degree rules beyond `N=18`, and any transfer from `m<=53` toys to
   `m=83` (required gate per `crypto/AGENTS.md` §8a) or `m=131`. Extrapolations
   there stay **[proposed]**, never results.
