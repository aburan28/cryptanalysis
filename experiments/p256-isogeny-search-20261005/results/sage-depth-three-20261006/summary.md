# P-256 horizontal search through depth three

## Traversal result

SageMath 10.6 traversed the rational horizontal graph generated by prime
degrees `3,5,11,13` through depth three while retaining every explicit path,
kernel polynomial, rational map, and transported P-256 generator.

| Maximum depth | Total curves | New curves at final depth | Search time |
| ---: | ---: | ---: | ---: |
| 2 | 24 | 17 | 3.709 s |
| 3 | 56 | 32 | 11.415 s |

Every retained path verified. Every curve had geometric automorphism order 2;
no exceptional `j`-invariant or extra automorphism was found. The largest path
degree product at depth three was `2197 = 13^3`.

## Depth-two timing screen

All 17 newly discovered depth-two neighbors were benchmarked in three blocks.
Each block included P-256, warmed every curve, and used one complete rotation
through all timing positions. Trials were one second each.

The three largest paired point estimates were:

| Path | Screening speed | Screening 95% interval |
| --- | ---: | ---: |
| `3,11` | 1.028x | 0.989–1.068 |
| `5,13` | 1.027x | 1.000–1.054 |
| `3,13` | 1.023x | 1.0001–1.047 |

The `3,13` result barely cleared an unadjusted 95% interval during screening.
It was one of 17 comparisons on a non-isolated host and was treated only as a
candidate for independent retesting, not as a speedup discovery.

## Independent holdout retest

The three screening leaders were retested against P-256 with fresh timings:
20 two-second trials per curve, a 0.2-second warm-up, and five complete
forward/reverse timing-position rotations.

| Path | Holdout speed | Holdout 95% interval | Significant |
| --- | ---: | ---: | :---: |
| `3,11` | 1.008x | 0.989–1.026 | no |
| `3,13` | 1.015x | 0.993–1.038 | no |
| `5,13` | 1.013x | 0.996–1.032 | no |

All rho linear-relation checks passed. None of the screening leaders survived
even an unadjusted holdout test, so a three-comparison correction is moot. No
depth-two candidate advances to an optimized-backend or per-key mapping study.

The 32 new depth-three curves were not wall-time benchmarked. They exposed no
exceptional structure, while the complete depth-two screen and fresh holdout
showed that percent-level Python timing fluctuations were not reproducible.
Benchmarking another generic layer on the same non-isolated interpreter would
not materially strengthen the cryptanalytic claim.

## Cost accounting

- Reusable discovery: 3.709 seconds through depth two and 11.415 seconds
  through depth three, excluding container startup.
- Per-key mapping: formulas for both source points are retained; evaluation is
  still untimed.
- Per-key ECDLP: reference rho iteration rates were measured for all 17 new
  depth-two curves and retested for the three screening leaders.
- Host isolation: unverified. These are exploratory reference-Python timings.

## Class-number attempts

The exact explored fraction could not be certified in this run:

- PARI `qfbclassno` failed with `precision too low in truncr`.
- PARI `quadclassunit` produced no result and was stopped after approximately
  12 minutes. The outer timeout signaled the Docker client but did not stop the
  container, so the exact named container was then stopped explicitly.
- An `lfun(quadchar(...),1)` fallback failed before computation because this
  PARI build did not expose `quadchar` in that form.

These failures are not evidence about the class number. They show only that an
exact class-group computation was not obtained within the bounded local attempt.

## Claim boundary

This run supports a narrow negative result: among 23 explicitly reached
neighbors through depth two, no reproducible Pollard-rho iteration-rate speedup
was found, and 56 total curves through depth three exposed no exceptional
automorphism structure. It is not an exhaustive class-group search and does not
rule out a distant arithmetic model or a genuinely non-generic algorithm.
Without measured path evaluation on both public points, it also cannot establish
an end-to-end per-key P-256 attack speedup.
