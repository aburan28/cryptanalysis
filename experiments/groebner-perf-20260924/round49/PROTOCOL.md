# Affine projection protocol

The input is the same freshly specialized branch-major table as round44: equation bits packed into one 32-bit word per constant, linear or square-free quadratic feature. Metal supports 1..32 equations and 1..10 residual variables, SIMD width 32 and 128 threads per threadgroup. The original lifted RREF and constant contradiction output retain their exact 34-word layout and semantics.

A second reduction continues inside each SIMD group, carrying `row = XOR(original_equation[j] for j in witness)` through every swap and XOR. Quadratic-column forward elimination leaves precisely the row combinations whose quadratic coefficients vanish. Gauss–Jordan elimination of the remaining linear columns gives a basis for the affine consequences, possibly together with the constant one. This is the kernel/image property of invertible row operations; it does not require generic rank, a planted solution or field normalization.

The new output has `y+2` 64-bit cells per branch:

- Cell zero: low 32 bits contain a valid marker at bit 31, quadratic rank in bits 0..7, affine linear rank in bits 8..15 and constant-one presence at bit 16. Other bits are zero. High 32 bits count row XORs in this additional device reduction.
- Cells 1..y: low 32 bits contain an affine polynomial with constant at bit zero and variables at bits 1..y; high 32 bits contain the original-equation witness. Unused slots are overwritten with zero.
- Cell y+1: the constant-one row and its witness, or zero.

The Metal source uses explicit pairs of 32-bit words. It does not require 64-bit SIMD shuffles. All slots of every dispatched representative are overwritten each solve. Symmetry aliases are handled by the existing freshly guarded host mechanism; undispatched GPU slots are never consumed. A disabled-projection solve resets the host pointer and does not read old affine output. Context locking serializes coefficient upload, command completion, proof construction and configuration.

The host validates header, rank, row and witness extents, ordered pivots and reduced form. It copies at most `y+1` affine rows into bounded stack storage, then invokes the existing full-affine contradiction or partial-affine resolution. A full affine candidate is checked in the original specialized equations before constructing an affine multiplier identity. Insufficient rank or a satisfying candidate retains the existing Macaulay/original-variable fallback. All proof, root, assignment and host work limits remain in force, including staged partial-root rollback. Independent verification does not use device rank claims or the producer's coefficient table.

The specialization table remains capped at 64 MiB and the additional buffer is explicitly charged as `2^x * (y+2) * 8` bytes. The general shape bounds give a conservative 96 MiB ceiling for this buffer; the input-table limit further restricts simultaneous shapes. For the 27-variable `(x,y)=(18,9)` fixture it adds 22 MiB. Existing input, original output, dispatch parameters and branch-map buffers remain charged. There is no additional dispatch, upload or wait; device time includes both reductions, and GPU wall time also includes the shared input copy, command submission and completion. All costs are inside producer evaluation and complete-query wall time.

`GPUProjectionStats` reports requested/enabled state, dispatched representatives, branches whose device projection is consumed, copied affine rows, allocated additional output bytes, and additional device row XORs on the consumed branches. The last counter is deliberately not total device work: unused projections and the original lifted RREF are excluded. The host projection work budget excludes GPU operations; those operations have a separate fixed bound of at most `32 * features` row XORs per dispatched branch in the additional reduction. Existing projection counters report host work only. Projection time includes host witness import, multiplier construction and partial resolution; normalization and partial times are nested, not additive exclusive phases.

GPU/device failures remain explicit errors and unsupported shapes use the portable CPU path. The new package is opt-in. Device-specific automatic routing needs a repeated complete-query win against accepted CPU and Metal comparators, with conversion, transfer, proof construction, independent checking and curve replay included. Correctness, operation counts and component timings alone do not meet that condition.
