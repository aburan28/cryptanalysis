# Shared producer Metal coefficient transform

This opt-in integration applies the validated round67 ascending, branch-major
uint32 subset transform directly to the round51 producer's existing Metal input
buffer. The following quadratic projection consumes that same invocation's
transformed device table, avoiding another full upload. The independent round66
checker retains its separate feature-major transform, buffers and proof checks.

The default remains `producer_transform='cpu'`. Explicit choices are `cpu`,
`metal` (one dispatch per bit), and `metal_tiled` (up to four initial stages
per tile). GPU modes require a compatible Metal producer with at most 32
equations, the existing 64 MiB table limit, and actual pipeline/device
capabilities. Unsupported requests fail explicitly. Wider equation sets and
systems without Metal keep their portable CPU paths.

Every invocation validates and scatters fresh packed ANF coefficients. The
GPU path uploads that fresh table, transforms it, waits for completion, and
copies it back. The original exact symmetry guard and host proof/fallback
code still consume the host table. The later projection skips its upload
only after validating a nonzero, current, single-use generation and the
original host pointer and extent. The producer does not modify either
coefficient copy between transformation and projection. Readiness is revoked
on consumption, new calls, configuration changes, all failed operations, and
scope exit. No specialized coefficients or target answers survive as reusable
answers. Only invariant layout, pipelines and allocated capacity are reused.

The borrowed helper retains strong references to the producer's ordinary
Metal queue and explicitly tracked shared buffer. It validates device,
storage mode, hazard policy and exact extent. It allocates no second full
coefficient table. `additional_table_bytes` consequently records zero; this
is not a claim of zero pipeline or metadata memory. Existing resident buffer
sizes remain separately accounted for.

`producer_transform_stats` is retained for successful results and native
failures. It records requested/executed mode, invocation generation, projection
upload/reuse bytes, and nested kernel copies, encoding, submitted/completed
dispatches, device time and wall time. Transform time belongs inside the
existing producer specialization interval. Device time is nested in wall
time and must not be added again. Failed later proof-budget attempts retain
GPU work that already executed. The public legacy statistics ABI is unchanged.

The native producer, Metal backend and kernel host wrapper are generated by
small substitutions into hash-pinned sources. The generated Python producer
adds the new accounting while retaining the existing result-owner lock and
failure metadata. A separately loaded reference query factory uses the old
round51 producer. The validator explicitly asserts the reference/candidate
binary paths and the unchanged checker path. An API regression test prevents
the candidate factory from replacing the baseline factory.

Validation covers:

- Exact shared-buffer transform and projection equality, single-use and stale
  generations, pointer/extent errors, disabled configuration, fresh reuse and
  borrowed-resource lifetime. The native backend controls also inject a failed
  pipeline configuration and check that the preceding valid mode remains usable.
- Optimized and UBSan native producer builds, equation widths 1–128, original
  failure/budget behavior, independent malformed-proof rejection, concurrent
  callers, fresh inputs, and exact old-producer outputs and counters.
- The 18 frozen original-ANF workloads spanning 6–27 total variables, with
  serial/prepared/overlapped independent verification. With Metal available,
  there are 732 complete queries and 24 unsupported planned cells: eight
  explicit GPU-transform setup requests on the 83-equation control each make
  three preparation schedules unavailable. Each setup is attempted and timed
  once; those cells execute no query and do not count as verified results.
  The CPU-only panel has 108 complete queries. The wide control still has
  successful portable CPU and explicit Metal-backend CPU-fallback controls.
- A separate pure-Python original-ANF replay of every distinct proof and exact
  Boolean basis. Retained artifacts are checked by hashes and Git source blobs;
  downloaded native binaries are never executed by the artifact auditor.

Run through ordinary Python after building the same native dependencies used
by round66. The dedicated CI workflow records that full build sequence.

```sh
python3 experiments/groebner-perf-20260924/round68/build.py --metal
PRODUCER_TEST_METAL=1 python3 -m unittest discover -s experiments/groebner-perf-20260924/round68 -p 'test_producer.py' -v
python3 experiments/groebner-perf-20260924/round68/validate_queries.py --metal --output /absolute/evidence/correctness.json.gz
python3 experiments/groebner-perf-20260924/round68/audit_queries.py --input /absolute/evidence/correctness.json.gz --output /absolute/evidence/original-anf.json
python3 experiments/groebner-perf-20260924/round68/measure_queries.py --metal --output /absolute/new/diagnostic-directory
```

Omit Metal flags/environment selection for CPU-only runs. A missing requested
device stays an explicit availability result. A successful compilation does
not establish physical GPU coverage.

The diagnostic compares the unchanged producer with all three integrated
transform modes, using both CPU and SIMD Metal independent checkers. The
eight-arm Williams design balances positions and all ordered neighboring pairs,
with 24 observations per arm and case. The CPU-only two-arm control has six
observations per arm and case. Each query freshly solves and independently
certifies the basis, checks original equations, and replays the public point;
copies and synchronization are included. Target-independent context and
pipeline setup are recorded separately. Failures are retained. No result is
promoted without the repository's host-isolation receipt: timing eligibility
is false and aggregate speedup is unknown on ordinary hosts.

These are polynomial-query stage diagnostics, not complete one-target IC/DLP
recoveries. This integration changes neither the asymptotic work of the subset
transform nor the applicability conditions of the underlying Boolean solver.
It does not establish a new general F4, F5 or F6 algorithm.
