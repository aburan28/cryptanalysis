# F6 research: a certified change of representation

Status: **implemented research control; no novelty claim and no general new
complexity result**. The useful question is whether a solver should switch
representations before its degree-driven matrices become expensive. Calling
an implementation F6 would not establish a new algorithm.

## Implemented and checked

`boolean_dual.cpp` implements the following exact algorithm in the Boolean
ring R = GF(2)[x_0,...,x_(n-1)]/(x_i^2+x_i), in graded reverse lexicographic
order. It returns the same complete reduced squarefree Gröbner basis as the
existing hybrid, rather than returning only one root.

1. Pack up to 64 input equations into a machine-word coefficient at each
   squarefree monomial mask. Duplicate terms cancel by XOR.
2. Apply the subset Möbius transform. At assignment a, each bit of the
   resulting word is the value of one input equation. Process further groups
   of 64 equations if needed and retain only assignments satisfying every
   group. This enumerates the **complete** zero set Z.
3. Run a Boolean version of Buchberger–Möller interpolation on Z. Visit a
   frontier of monomials in increasing grevlex order. Maintain an echelon
   basis of their evaluation vectors and the exact combinations of accepted
   standard monomials. An evaluation dependence gives a vanishing polynomial;
   an independence adds a standard monomial and its variable multiples to the
   frontier. Discard multiples of known leading monomials.
4. Return the reduced basis. Stop explicitly as `INCONCLUSIVE` if the complete
   point set exceeds the configured interpolation cap; never truncate the
   points and return the ideal of a subset as a completed answer.

The executable accepts n <= 24 and currently caps interpolation at 256 roots.
The independently certified PDP wrapper is deliberately limited to n <= 20.
The library wrapper reuses loaded machine code, with fresh numerical state on
every call. The subprocess wrapper supplies a hard process timeout; the bounded
in-process call does not supply an interruptible wall-clock timeout.

This route is attractive for the retained tiny point-decomposition systems,
which have small complete solution sets. It does not establish performance
for large cryptanalytic systems. Exhaustive enumeration is still exponential.

## Correctness of the independent certificate

The Python certificate does **not** trust the solver's roots or interpolation
rank. It computes the input zero set independently with monomial truth bitsets,
using AND and XOR, rather than the C++ subset-transform/interpolation code.

Let G be the proposed squarefree basis and let S be the squarefree monomials
not divisible by any LM(g), including 1 when appropriate. Let J be the ideal
generated by G together with the Boolean field equations in the ordinary
polynomial ring. Check:

- every g in G vanishes on every point in the complete input zero set Z;
- |S| = |Z|;
- the leading monomials are pairwise nondividing, and all tails belong to S.

The first condition gives J ⊆ I(Z), hence dim(R/J) >= |Z|. The monomial ideal
generated by the proposed leading monomials is contained in the true initial
ideal, giving dim(R/J) <= |S|. Equality forces both ideal equality and equality
of initial ideals. Thus G is a Gröbner basis of the original Boolean ideal;
the final condition makes it reduced. Boolean ideals are radical because the
quotient ring is a finite product of copies of GF(2).

This also detects a defect of the old acceptance condition: G = [1] passes
"G is a GB" and "all input generators reduce to zero" even when the original
system has solutions. Our certificate rejects this because it loses input
roots. Original-generator reduction was only one ideal containment.

The default truth-bitset implementation caches every monomial at n <= 12,
using O(4^n) **bits**. The additional uncached mode supports n <= 20, retaining
only n variable truth tables and reconstructing each monomial by AND. Its
space is O(n 2^n) bits and time is O((n + sum of input/output term degrees)
ceil(2^n/word_size)), plus checks on leading terms and tails. Both modes are
cross-checked against the independent Singular oracle. This bounds the complete
verified route by 2^n times polynomial factors without requiring the O(4^n)
cache; it remains an exponential and explicitly bounded method.

## Conditional complexity, not a universal improvement

Write q = ceil(m/64), R = |Z|, and L for input length. In a word-RAM model,
the current evaluation costs O(L + q n 2^n) word operations and O(2^n) words
plus the packed input. The interpolation visits at most 1+nR generated
frontier candidates before divisibility pruning. A conservative bound for
this implementation is

    O(n R^2 ceil(R/64) + n^2 R^2 + n R log(nR))

word operations/comparisons, with evaluation-vector and combination storage
O(R ceil(R/64)), frontier storage O(nR), and up to O(nR^2) output terms.
The quadratic-in-n term accounts for the simple linear scan of leading
monomials; an indexed divisibility structure could improve it.

When R is small and a dense degree-D Macaulay formulation has N_D approaching
2^n columns, this replaces a potentially cubic dense elimination with a
near-linear-in-2^n transform plus a small point-ideal computation. That is a
conditional asymptotic advantage over **that dense matrix model**. It is not
a proof of beating sparse F4/F5 on arbitrary input, nor a new solution to the
worst-case Boolean solving problem. Large R makes interpolation unattractive;
small-degree structured inputs may be solved cheaply by F4 long before a full
enumeration would finish.

The current implementation uses the elementary n2^n transform. Published
degree-sensitive FES/space-efficient Möbius methods can improve evaluation to
O(d2^n) and use much less workspace. They are the relevant next baseline.

## Prior art that constrains a novelty claim

- [Bouillaguet, Boolean polynomial evaluation / BeanPolE](https://eprint.iacr.org/2022/1412)
  describes FES and space-efficient Möbius evaluation, packed Boolean systems,
  and their use in more sophisticated solvers. Our transform is an elementary
  implementation, not a new evaluation algorithm. The full paper also discusses
  Crossbred outperforming exhaustive search on larger random dense systems.
- [Just–Stigler, ideals of points](https://arxiv.org/abs/0711.3475) develops
  faster point-ideal Gröbner construction when the point set is small relative
  to the variable count. Buchberger–Möller itself is established prior art.
- [M5GB](https://arxiv.org/abs/2208.00844) already combines signatures with
  tail-reduced reducer reuse. That combination cannot be our novelty claim.
- [EGHAM2](https://eprint.iacr.org/2020/1255) specifically addresses Boolean
  equation systems with few solutions. "Exploit small solution count" alone
  is also established prior art; its actual method differs from this control.
- [Chordal networks](https://arxiv.org/abs/1604.02618) exploit graphical
  structure and compact triangular representations. A separator-based solver
  needs a contribution beyond simply applying this existing principle.
- [Proper-Cover, July 2026](https://arxiv.org/html/2607.09163v1) treats one
  variable as a polynomial coefficient parameter, with signature-based cover
  and factor-dependent refinement. Its output is a proper basis assembled
  from modular components; that output contract must be distinguished from a
  reduced grevlex basis. Section 5 compares unoptimized Maple implementations,
  not today's fastest native F4 packages. We read the algorithm and experimental
  setup but have not implemented or independently reproduced its claims.

## A specific F6 hypothesis to pursue

The candidate research direction is **certified switching between a partial
Macaulay computation and a small quotient representation**, with reusable
family computations. The separate pieces are known. The open contribution
would be a sound, inexpensive trigger and a reusable family representation
that avoid constructing most of the expensive high-degree matrix.

Proposed schedule:

1. Start with sparse, signature-legal algebraic reductions and a strict
   work/memory budget. Retain provenance for every consequence.
2. Track a standard-monomial upper bound from known leading terms, the next
   degree's predicted matrix shape, and actual costs of partial evaluations.
   The upper bound is not a measured solution count and cannot certify
   completion by itself.
3. If verified linear consequences lower the number of free variables,
   substitute them exactly. Decide between another algebraic degree step,
   complete enumeration of the reduced coordinates, and a certified split.
   Enumeration/splitting costs must include every branch and failed pilot.
4. Use the small exact point set or certified quotient representation to
   reconstruct the requested basis. For a roots-only task, explicitly change
   the output contract instead of charging a roots-only solve as a GB solve.
5. For families F(x;t), investigate coefficient functions
   F_i(x;t)=sum_j c_ij(t) h_j(x). Reuse evaluations of h_j only when that
   symbolic identity is proved, including exceptional specializations.
   A sampled shared numeric row space is not proof that it applies to an
   unseen target. The five existing PDP targets have no identical source
   generators in common, so literal equation caching is insufficient.

To claim an asymptotic contribution, prove a parameterized bound in the number
of free variables, quotient dimension, family coefficient rank, or separator
width, and exhibit a family on which the controlling parameter provably grows
more slowly than the ordinary Macaulay column count. Comparing a few timings
or observing a degree drop is not that proof.

Required next ablations are F4 alone, fast exhaustive search alone, interpolation
alone with already-known roots, the combined control, and the proposed adaptive
schedule, all with the same requested output and charged preparation. Evaluate
unseen targets and random/structured controls; retain root-cap failures and
timeouts. No new degree-of-regularity bound has been established in this round.

## GPU implications

`batch_rref.metal` computes **complete** exact GF(2) rank and RREF for independent
matrices, one threadgroup per matrix. On-chip padding avoids power-of-two bank
conflicts; SIMD minimum reductions replace contended pivot-search atomics.
All output words and ranks are compared with M4RI, including rank-deficient
and pivot-gap cases. Captured real matrices are tested alongside synthetic ones.

This does not allow unrestricted elimination of signature-labelled F5 rows.
The caller must preserve the legal reduction order or establish a separate
signature-safe batching rule. It is currently a matrix throughput prototype,
not a production F4/F5 GPU dispatcher. The whole padded matrix must fit in
the device's threadgroup memory, which excludes the current n=12 Macaulay
matrix. Large matrices need tiled panels or a sparse/dense block decomposition.

The dual evaluation path offers another GPU target: independent transforms
over many targets or independent variable slices. Its short local CPU runtime
means a GPU dispatch is unlikely to win on one current n=12 target. Residency,
large batches and larger n are prerequisites worth measuring, not assumed wins.

All these measurements concern the internal PDP algebra stage. They contain no
complete IC candidate, recovered subgroup logarithm, final relation-matrix LA,
calibrated rho ratio or end-to-end DLP speedup. Those remain unknown.
