# Certified four-corner selection for secp256k1 U14 multiplication

The native U14 evaluator now certifies a unique nearest Eisenstein cell corner from two reciprocal-product fractional limbs and constructs only that corner. The certificate uses signed 128-bit interval scores; ambiguous cells retain the exact four-corner norm selector. The existing point table and evaluator are shared with the parent reciprocal mode.

The [protocol](PROTOCOL.md) derives the four score intervals and proves that a strict interval winner has the same representative as the exact selector. The [independent screen](screen-result.json) checked exact quotients, corner scores, representatives, scalar congruence, and 128 independently replayed points. Across 8,715 boundary, frozen, prior, and newly frozen scalars, all 8,715 corners were certified and the fallback count was zero. The [fresh input](fresh-inputs.json) scalar digest is `dc7f33ee5c711a11ae66a7ecfda766fedf3b81648afa5b4369f2000379e04ea5`.

The [native verification receipt](verification.json) binds the source, inputs, executable, and raw outputs. All **69 release tests passed**. The new native test paired modes 120 and 121 on all 8,715 scalars, comparing representative, addition count, retained table bytes, and complete point; 128 holdout points also matched independent binary double-and-add. Both fixture modes verified all **129 points** and produced identical per-case fields apart from their mode labels. The raw [test log](native-tests.log), [reference fixture](reference-fixture.stdout.txt), and [candidate fixture](candidate-fixture.stdout.txt) are retained.

For each certified scalar, the selector replaces the parent's four-corner BigInt norm and inner-product scoring with four BigInt coordinate products and small integer interval arithmetic. Both modes retain two fixed-limb reciprocal products and the same U14 point evaluation. A failed certificate invokes the exact parent selector. The operation reduction is a source-level result; a paired CPU timing result needs the host isolation receipt specified in [the repository benchmark rules](../../docs/ISOLATED_BENCHMARKS.md).

The [RunPod correctness script](runpod_correctness.sh) is queued on the existing serial worker; see the [dispatch record](RUNPOD_DISPATCH.md) for the immutable archive digest, job IDs, and lock handoff. Its container does not meet the repository's host isolation gate, so that worker can provide physical x86 correctness evidence and exploratory diagnostics only. The public-source archive transfer passed automatic approval review after repository visibility and tracked-file checks.
