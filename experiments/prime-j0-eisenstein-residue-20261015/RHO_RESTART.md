# Norm-4033 fixed-base multiplication in rho restart work

The matched restart-kernel experiment isolates `aG+bQ`, the scalar work used to construct jump points and walker starts in rho. The [cryptanalysis C rho](../../src/rho.c) computes two scalar multiples and one addition for each jump and restart; its walk step adds a precomputed jump. The separate `crypto` repository's `pollard_collab` job context uses the same `aG+bQ` shape for branch construction, walker starts, and verification. That code accepts general curves, so a secp256k1 specialization requires exact curve and generator checks.

The [frozen fixture](rho-restart-first128-fixture.json) fixes secp256k1, a target point `Q` from index 256 of the archived uniform scalar fixture, and 128 independent public `(a,b)` pairs from indices `0..127` and `128..255`. The [independent auditor](analyze_tier1_rho_restart_hybrid.py) replays every measured `aG+bQ` with separate affine arithmetic and verifies the fixture derivation. Both comparison arms run in the same [native binary](rho-restart-hybrid-native-provenance.tar.gz):

- **OpenSSL reference:** one `EC_POINT_mul` computes `aG+bQ`, followed by affine serialization.
- **Hybrid:** the norm-4033 fixed table computes `aG`; the candidate converts that point to OpenSSL coordinates, computes `bQ` with OpenSSL, adds the points, and serializes the result.

The measured interval includes all operations just named. Fixture parsing, group setup, one OpenSSL warmup, the hybrid's reusable table preparation, and process launch are outside it and recorded separately. The [hash-guarded overlay](native_rho_restart_hybrid_overlay.py) inserts the [Rust comparator](rho_restart_hybrid.rs) into the previously archived norm-4033 source; the native provenance contains exact source, transitive arithmetic source, binary, fixture, linked `libcrypto`, and build logs.

| --- | ---: | ---: | ---: | ---: | --- |
| One restart | 0.205 ms | 0.345 ms | 0.610× descriptive | [0.589, 0.617] | Failed: two A/A calibrations |
| 128 restarts | 25.965 ms | 35.926 ms | 0.723× qualified | [0.717, 0.727] | Passed |

Each panel completed 96 valid arms and 48 valid pairs. The [one-restart plan](tier1-rho-restart-hybrid-1-cpu40-manifest.json), [rules](tier1-rho-restart-hybrid-1-cpu40-rules.json), [launch](tier1-rho-restart-hybrid-1-cpu40-launch.json), [audit](tier1-rho-restart-hybrid-1-cpu40-audit.json), and [raw archive](rho-restart-hybrid-1-raw.tar.gz) preserve the calibration ratios **2.083** and **1.188**, outside the frozen `[0.90,1.11]` gate. Its aggregate result remains unknown. The [128-restart plan](tier1-rho-restart-hybrid-128-cpu40-manifest.json), [rules](tier1-rho-restart-hybrid-128-cpu40-rules.json), [launch](tier1-rho-restart-hybrid-128-cpu40-launch.json), [audit](tier1-rho-restart-hybrid-128-cpu40-audit.json), and [raw archive](rho-restart-hybrid-128-raw.tar.gz) preserve the qualified comparison. Mean excluded preparation was **49.293 ms** for the hybrid and **1.123 ms** for OpenSSL in that panel.

The full restart kernel favors OpenSSL in this implementation. The fixed-table `aG` gain observed in isolation is spent on the affine string conversion, the arbitrary-point `bQ` multiply, and the final addition. A joint norm-4033 Horner evaluation can share the 22 projective steps between both public scalar streams and remove the per-restart cross-library conversion. Its target-specific Q table, full target accounting, and matched Linux timing are the next experimental gates.

## Joint Horner candidate

The [joint native source](joint_norm4033.rs) and [rho fixture command](rho_restart_joint.rs) implement that shared chain. The [hash-guarded overlay](native_rho_restart_joint_overlay.py) applies them to the archived hybrid comparator source while preserving its OpenSSL reference command. Both scalar streams use the exact norm-4033 selector and canonical six-unit digit tables. The candidate holds one projective accumulator; each of its 22 steps applies `64 + ω` once and adds at most one G digit and one Q digit. The Q digit and terminal tables are built once for the fixed target point. The command separately reports generator preparation, target-specific Q preparation, and the restart kernel. A one-target online comparison must charge Q preparation once; a 128-restart kernel panel can show its amortization only as a secondary result.

A local macOS ARM64 release build passed `cargo check --offline --locked` and `cargo build --release --offline --locked`. The archived source refers to eight external atlas files and three auxiliary fixtures absent from the compact provenance bundle; the local build used empty placeholders for the unused atlas paths and auxiliary fixtures, and the exact archived uniform fixture for the exercised scalar selector. Those placeholders are build-only and are excluded from the joint pilot's execution path. The local joint command exactly replayed the first case and all 128 frozen `aG+bQ` outputs. The current full-table command reports **709,220 retained payload bytes**, including the G table, reusable seed order, and target-specific Q table; a full cost and measurement receipt awaits the Linux build. Local time samples are correctness diagnostics under an unisolated host and have no benchmark tier.

The target-table builder now batch-normalizes its nonidentity digit and terminal points with **one field inversion**. If `P_i` is the product of the earlier projective `z` coordinates, the reverse accumulator starts at the inverse of the total product. At index `i`, multiplying it by `P_i` gives `z_i⁻¹`; multiplying it by `z_i` leaves the inverse of `P_i` for the next index. The final accumulator is checked against the Montgomery representation of one. This replaces an inversion for each table point with one inversion and linear field multiplications. The [independent replay script](verify_joint_q_batch.py) and [local receipt](joint-q-batch-local-replay.json) cover one and 128 fixed-Q restarts plus four additional Q values (`G`, `2G`, `3G`, `7G`) with eight independently computed `(a,b)` results each. The full-table, on-demand, and fused commands passed **483 exact outputs**, four explicit fused edge cases exercised point doubling, opposite points, zero scalars, and a one-sided digit, and the no-warmup OpenSSL reference passed the one- and 128-restart fixtures: **616 exact outputs** in 24 serial runs. Those replays establish exact output for the tested inputs; Linux timing and peak preparation memory remain to be measured.

The on-demand command, `--pilot-rho-restart-joint-demand`, recodes the frozen public `b` values, selects only their nonzero Q digit and terminal seed indices, batch-normalizes those points, and evaluates the shared Horner chain. Its `online_ms` includes target-specific preparation plus all requested restart evaluations; globally reusable G and canonical seed preparation remains separate. The one-restart fixture constructed **21 Q points** and retained **453,204 bytes** of G, seed, and sparse Q payload. The 128-restart fixture constructed **659 Q points** and retained **519,556 bytes**. These are local source and allocation counts, not isolated wall-time comparisons. The hash-guarded overlay was reapplied to a fresh copy of the archived base source; all four generated Rust files matched the locally compiled source byte for byte.

The fused command, `--pilot-rho-restart-joint-fused`, uses the same sparse Q preparation, then forms each needed affine G-plus-Q digit with one batch inversion of pair denominators across the requested restarts. It evaluates the 22-step shared Horner chain with at most one mixed digit addition per step and batch-normalizes all finite outputs with one more inversion. The affine pair builder covers distinct x coordinates, equal-point doubling, and opposite-point identity. For the frozen 128-restart workload, it formed **2,805 pair sums**; its target-dependent path executes one inversion for Q normalization, one for the pair denominators, and one for the finite outputs. The on-demand path executes one Q-table inversion and one output inversion per restart, **129** across 128 restarts. `JointHorner4033.joint_eq_sum` supplies the checked group-level identity for fused digits under its stated endomorphism and point-map hypotheses; native affine-formula refinement remains a separate proof obligation. The current local replay and operation counts are ready for a matched Tier 1 panel.

The [joint Horner Lean module](JointHorner4033.lean) states the shared-chain identity for two equal-length streams under associative, commutative point addition and a norm-4033 endomorphism that preserves addition (`joint_eq_sum`). It also connects two exact scalar recoding traces to the shared two-base point (`joint_of_valid_traces`). The map premises retain the exact curve and endomorphism bridge required for secp256k1; source-level refinement from the native projective formulas and table construction remains open. The [pinned Lean 4.34.1 build receipt](joint-horner-lean-check.json) records an axiom-free `joint_eq_sum` and standard `propext` for `joint_of_valid_traces`; the [checker](check_joint_horner_lean.py) rebuilds fresh imports and audits both declarations. `lean4checker --fresh` was unavailable locally.

The [Tier 1 comparison plan](RHO_JOINT_BENCHMARK_PLAN.md) uses the same native binary for OpenSSL and joint arms, the frozen 1 and 128 restart fixtures, alternating order, bracketing A/A controls, independent point replay, source and binary hashes, and serial execution on the existing RunPod benchmark worker. The `openssl_nowarm` reference times its first target multiplication; the older OpenSSL comparator warmed that multiplication before its timer. The new [plan generator](make_tier1_rho_joint.py) derives deployed source hashes from the archived base plus the hash-guarded overlay and accepts the Linux binary and `libcrypto` hashes only after the target build. No Tier 1 timing for this candidate has been recorded.

The [shared Q-seed graph](JOINT_SEED_GRAPH.md) is a second target-table construction path. It applies the curve automorphism and sign to earlier requested points, then constructs a new digit through one group addition with a shared Q power or another earlier point. Isolated points retain the direct builder. On the frozen 128-restart stream, 658 of 659 requested Q seeds use graph edges, reducing seed-construction `add_projective` calls from 4,098 to 667; the one-restart count changes from 113 to 62. Graph search and unit rotations are charged target costs, so these source-level call counts are not wall-time speedups. The [operation-count receipt](joint-seed-graph-local-profile.json), [1,268-output exact replay](joint-q-graph-local-replay.json), and [Lean graph proof](JointSeedGraph.lean) support the new path. The revised Tier 1 plan compares direct, online graph, and scalar-stream-precompiled graph builders for shared Horner and fused-pair evaluation. The precompiled graph is target-independent setup with its time and memory reported separately.

## Joint digit-pair reuse screen

The [exact native profile](profile_joint_pairs.py) tests a second format: precompute sums of a G digit and a Q digit so each joint Horner step uses one point addition. It counts raw digit pairs and pairs identified by a common six-unit action, using the same frozen scalar recoder as the full and sparse paths. The [source-bound local receipt](joint-pair-profile-local.json) records these counts without using host wall time.

| Frozen restarts | Steps with both digits | Distinct raw pairs | Distinct common-unit orbits | Maximum net additions saved before lookup and memory costs |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 22 | 22 | 22 | 0 |
| 128 | 2,805 | 2,788 | 2,755 | 50 |

The bound charges one point addition to prepare each distinct common-unit pair and credits one saved addition on every use. For this input law, a persistent pair-sum table would prepare 2,755 points for at most 50 net saved additions, before normalization, lookup, and memory costs. This directs the next experiment toward **per-restart batched pair fusion**: form only that restart's 22 sums with a shared inversion, then test its complete target-charged cost. The profile is a combinatorial screen, not a wall-time result.
