# Balanced-pair group accumulation screen

The prototype keeps every selected point in the balanced Eisenstein pair field through the radix-14 group sum. A unit rotation becomes a coefficient permutation before group addition, and the table retains 28,825,228 bytes. It reproduced every point in the 12,288-scalar frozen uniform fixture.

The [hash-guarded overlay](native_pair_accumulation_overlay.py) converts the frozen norm-136531 affine table to compact balanced `(x,y)` pairs during preparation. The timed path selects the compact entry, applies the unit rotation and sign, joins the selected points with pair-field Jacobian mixed additions, batch-normalizes the 128 outputs, and converts only the final affine coordinates to conventional Montgomery field elements. Its [native provenance archive](pair-accumulation-native-provenance.tar.gz), SHA-256 `2f36e7c6d52a85790f17428daedec09c95d3c3e936f44a655c18725ecb2c9c1f`, includes the compiled executable, source, first compiler error, corrected build, fixture, stdout, and stderr. The [receipt auditor](audit_pair_accumulation.py) produced [this exact-replay record](pair-accumulation-audit.json).

The full-stream diagnostic reported 1,036.845373 ms for 12,288 outputs after 4,900.576860 ms of table preparation. The ordinary-field two-x and cache paths reported roughly 64–68 ms in nearby diagnostics, a gap large enough to reject this direct pair-field accumulation as the next timing candidate. These diagnostics are not a qualified Tier 1 comparison. The result directs the next experiment toward reducing ordinary-field group-operation cost while retaining cheap table selection.
