# Units of work

## `bitop/v1`

One bit operation is one two-input Boolean gate (AND, XOR, OR) in the textbook
circuit for a primitive; a cost is `Σ count(primitive) · gates(primitive, width)`,
an exact integer that no host enters. The convention, its derivations and the
reasons for it are `crypto:docs/units/BITOPS.md`; the reference implementation is
`crypto:src/cryptanalysis/bitops.rs`. The convention is frozen: a different one is
`bitop/v2`.

| file | what |
|---|---|
| [`bitop-v1.vectors.json`](bitop-v1.vectors.json) | the 243 reference vectors (gates as decimal strings) every implementation must reproduce exactly |
| [`tools/bitops.py`](../../tools/bitops.py) | this repository's Python implementation |
| [`tests/test_bitops.py`](../../tests/test_bitops.py) | reproduces every vector row, checks the generated set equals the committed set, and checks the copy is byte-identical to its source |

**Source of the vectors.** `bitop-v1.vectors.json` is a verbatim copy of
`crypto:docs/units/bitop-v1.vectors.json` (repository `aburan28/crypto`, branch
`claude/bitop-work-unit`, commit `4d9760b78`, generated by
`ecbench bitop-vectors`), SHA-256
`36a78bd8baf445307e2198ac49a79394138b4e7ae9d7cb7028cf1536e35132d8`. Never edit
the copy; refresh it from the source and update the digest in the test.

**Where it is used.** `experiments/ic-bench` reports a `work` block in bitop/v1
beside its rps figures; the counter-to-primitive mapping is in
[`experiments/ic-bench/README.md`](../../experiments/ic-bench/README.md#work-in-bitopv1)
and `experiments/ic-bench/bitop_work.py`.

## Rho reference

[`tools/rho_reference.py`](../../tools/rho_reference.py) is the one Pollard-rho
reference: the floor `sqrt(pi r / (2A))`, the one-target expectation
`sqrt(pi r / 2)` (the constant is `sqrt(pi/2) ≈ 1.2533` group operations per
`sqrt(r)`, not "about 1.3"), and the Kuhn–Struik batch series in the named
variants `generous` and `with_setup`. A ratio to rho is only compared with
another ratio under the same variant.
