# Repository review, 2026-09-25

This is a deep review of `aburan28/cryptanalysis`, done as the productionised
home of the tools developed in [`aburan28/crypto`](https://github.com/aburan28/crypto).
It covers the review itself and the changes made in response (PR #121). The
evidence is reproductions, not code reading alone: every bug below was run, and
the command that shows it is given.

## Summary

- **Code from `crypto` had not made its way here.** The suite was imported from
  crypto@413da466 on 2026-09-21. Since then `crypto` gained about 51k lines under
  `src/` (167 files) and about 20k in examples and tests. That includes the whole
  index-calculus framework (`ic_framework`, `ic_run`, `ic_engine`,
  `ic_boundary`, `curve_catalog`, …), the F4/F5 engines (`inherited_f4`,
  `f4_fp_tower`, `wide_groebner`, `matrix_f5_f2`, …), `gaudry_quartic`,
  `koblitz_isogeny_cost`, the `isogeny/` module, the `icx` tool and five new `ic`
  subcommands. The suite had also moved on by itself (prime-field orbit IC, the
  fast Boolean F4, the challenge corpus), so this was a three-way merge.
  **Now ported:** 22 modules, `isogeny/`, `ca-icx`, the `ic` subcommands and 44
  examples. The merge was done file by file against the fork point, and both
  sides' features were kept.
- **The command-line story was fragmented.** There were about 15 executables:
  `cryptanalysis`/`ca`, `ca-suite`, `ca-ic`, `ca-curves`, the Python CLI and
  others. About 80 of 133 suite modules could be reached from no binary.
  **Now:** [`crax`](CRAX.md) is one binary with one subcommand per attack,
  covering the C library and the suite. The old binaries remain as shims.
- **No number field sieve existed**, and neither did most of the classical toy
  attacks: p−1, QS, Fermat, Wiener, Håstad, common modulus, batch GCD. **Now:**
  GNFS, SNFS, SIQS, p−1/p+1, rho, the RSA attacks and a full-factorisation
  ladder, all exposed as `crax` commands.
- **Three "attacks" were not attacks.**
  - `mov_attack.rs` used a "pairing" `(x1² + x2) mod n`, which is not bilinear.
  - `canonical_lift::smart_attack_anomalous` always returned `Err("not yet
    implemented")`.
  - `invalid_curve_attack.rs` takes the secret it claims to recover as an input.

  **Now:** Smart's attack works at any size (a 256-bit anomalous curve in about a
  second). MOV uses a real reduced Tate pairing (Miller's algorithm, F_{p^k} for
  k ≤ 12). Singular curves are handled. `crax ecdlp` dispatches among them. The
  invalid-curve simulation is still open (finding 4).
- **The C solvers ran forever on a target outside ⟨g⟩** (finding 1), and
  Pohlig–Hellman failed on non-cyclic groups. **Now:** the solvers check
  membership on entry, and Pohlig–Hellman decomposes by ord(base).
- **The network code is still not safe to expose** to untrusted peers (findings
  5–8). The one unauthenticated way to exhaust memory is fixed; authentication
  and peer identity are not.
- **Measured against the repository's own challenge corpus** (98 prime-field
  records): `crax challenge solve` solves all 47 `check`-tier records with p > 3,
  matching the stored logs. It also solves 9 `open`-tier records that have no
  published answer, including anomalous curves at 64–192 bits in under 0.2 s and
  a 160-bit class-number-2 CM curve by Pohlig–Hellman. It refuses the rest with a
  reason for each check. One open record has no solution at all (finding 18).

## What changed (PR #121)

- **Port.** Everything cryptanalytic in crypto@54e977ab is now in `suite/`,
  three-way merged against the fork point (216 files merged, 12 conflicting
  hunks in `koblitz_groebner.rs` alone, resolved by hand). Upstream's
  `#[allow]`s were replaced by code fixes, and upstream's `base64` dependency by
  a local codec. Not ported, because no attack module reaches them: cryptopals,
  zk, tls13, bls12_381, keys, encoding and the PQC CLIs.
- **`crax`.**
  - The C library's generic solvers, through `bindings/rust`.
  - `ecdlp`, `challenge`, `factor`, `gnfs`, `snfs`, `qs`, `ecm`, `pm1`,
    `rho-factor` and `rsa`.
  - Routing to the research command lines, which moved into
    `suite/src/cli/tools/`.
  - See [CRAX.md](CRAX.md).
- **New modules.**
  - `cryptanalysis::weak_curves`: Smart, MOV with a Tate pairing, singular
    curves, Pohlig–Hellman, budgeted factoring, and a dispatcher.
  - `cryptanalysis::factoring`: GNFS, SNFS, SIQS, p−1/p+1, rho, the RSA
    attacks, and automatic dispatch.
- **Fixes** to C library findings 1, 1b, 9, 13 and 14, and to suite findings 2,
  3, 3b, 5 and 11.

## Remaining gaps, in priority order

1. **Coordinator and `rho-collab` trust model** (findings 5–8): authentication,
   peer identity, TLS, and O(1) ingest. Until then, run them only among trusted
   machines.
2. **The invalid-curve attack as a real oracle attack** (finding 4). Also add
   ECDSA nonce reuse and HNP-from-signatures as `crax` commands; the lattice
   code (`hnp_ecdsa`, `multi_key_hnp`) exists but has no command.
3. **Binary-field and F_{p^k} curves in `crax challenge solve`.** Those records
   are reachable only through the `ic` tools.
4. **Corpus hygiene:** a CI job that recomputes ord(G), checks target ∈ ⟨G⟩ and
   cross-checks the orders (findings 10, 18).
5. **Index calculus in F_{p^k}^\*,** which would make MOV and the node case of
   the singular attack subexponential, not just a transfer.
6. **Factoring at scale:** lattice sieving, double large primes and Block
   Lanczos. The current sieves are measured and honest at 55–75 digits.
7. **Strict parsing in the C CLI** (finding 12). The Python CLI has no
   `--max-ops`.
